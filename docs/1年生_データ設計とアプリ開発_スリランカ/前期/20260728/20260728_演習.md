## අභ්‍යාසය 2: INSERT / UPDATE / DELETE

```sql
-- ① පහත පරිශීලකයා එකතු කරන්න
--    නම: 中村健二, ඊමේල්: nakamura@example.com
--    අපේක්ෂිත ප්‍රතිදානය: id=4 ලෙස 中村健二 එකතු වේ

-- ② products වගුවට "USBハブ" (මිල: යෙන් 2800) එකතු කරන්න
--    අපේක්ෂිත ප්‍රතිදානය: id=4 ලෙස USBハブ(යෙන් 2800) එකතු වේ

-- ③ 田中太郎 USBハブ 3ක් ඇණවුම් කළ වාර්තාව orders වගුවට එකතු කරන්න
--    ඉඟිය: මුලින්ම 田中太郎 ගේ id සහ USBハブ හි id SELECT මගින් පරීක්ෂා කරන්න
--    (පියවර 2කින් කළත් කමක් නැත. එක් ප්‍රකාශයකින් ලිවීමට කැමති අය පාඩම් ද්‍රව්‍යයේ 8 වන පරිච්ඡේදයේ "Subquery" කොටස බලන්න)
--    අපේක්ෂිත ප්‍රතිදානය: id=6 ඇණවුම ලෙස (user_id=1, product_id=4, quantity=3) එකතු වේ

-- ④ ノートPC හි මිල යෙන් 95000 ලෙස යාවත්කාලීන කරන්න
--    ඉඟිය: SELECT මගින් පරීක්ෂා කර UPDATE කරන්න
--    අපේක්ෂිත ප්‍රතිදානය: ノートPC හි price 98000 → 95000 ලෙස වෙනස් වේ

-- ⑤ එකතු කළ 中村健二 ගේ ඇණවුම් දත්ත තිබේ නම් ඒවා මකා, ඊළඟට 中村健二 ම මකා දමන්න
--    ඉඟිය: බාහිර යතුරු සීමාව (foreign key constraint) ඇති නිසා, orders මුලින් මකා දැමිය යුතුය
--    ඉඟිය: 中村健二 ගේ id නොදන්නා වුවද, පාඩම් ද්‍රව්‍යයේ 8 වන පරිච්ඡේදයේ "Subquery" කොටසේ දැක්වෙන ක්‍රමය භාවිතා කළොත්
--    (SELECT id FROM users WHERE name = '中村健二') ලෙස එක් ප්‍රකාශයකට එකතු කළ හැක
--    අපේක්ෂිත ප්‍රතිදානය: 中村健二 ගේ ඇණවුම් 0ක් නිසා පළමු DELETE හි ඉලක්ක 0යි,
--    දෙවන DELETE මගින් 中村健二(id=4) මැකී යයි
```

## අභ්‍යාසය 3: JOIN සහ සමුච්චය කිරීම (Aggregation)

(අභ්‍යාසය 2 හි වෙනස්කම් සිදු කිරීමට පෙර, පාඩම 09 හි ආරම්භක දත්ත පදනම් කරගෙන සිතන්න)

```sql
-- ① සියලුම ඇණවුම් "පරිශීලක නාමය・භාණ්ඩ නාමය・ප්‍රමාණය・මුළු මුදල" ආකාරයෙන් පෙන්වන්න
--    අපේක්ෂිත ප්‍රතිදානය: පේළි 5 (田中太郎×2, 鈴木花子×2, 山田次郎×1)

-- ② 田中太郎 ගේ ඇණවුම් ලැයිස්තුව භාණ්ඩ නාමය සහ මුදල සමඟ පෙන්වන්න
--    අපේක්ෂිත ප්‍රතිදානය: ノートPC(1ක්, යෙන් 98000), マウス(2ක්, යෙන් 6400) යන පේළි 2

-- ③ එක් එක් භාණ්ඩයේ මුළු විකුණුම් "භාණ්ඩ නාමය・විකුණූ ප්‍රමාණය・මුළු විකුණුම්" ආකාරයෙන්
--    මුළු විකුණුම් අනුව අවරෝහණ පිළිවෙළට පෙන්වන්න
--    අපේක්ෂිත ප්‍රතිදානය: ノートPC(3ක්, යෙන් 294000) → キーボード(1ක්, යෙන් 8500) → マウス(2ක්, යෙන් 6400)

-- ④ තවමත් කිසිදු ඇණවුමක් කර නැති පරිශීලකයින් සොයන්න
--    ඉඟිය: LEFT JOIN + WHERE orders.id IS NULL භාවිතා කරන්න
--    (මෙම රටාව පිළිබඳ පැහැදිලි කිරීම සඳහා පාඩම් ද්‍රව්‍යයේ 5-1 කොටස වන "තවම ඇණවුම් නොකළ පරිශීලකයින් පමණක් සොයා ගැනීම" බලන්න)
--    අපේක්ෂිත ප්‍රතිදානය: පේළි 0 (ආරම්භක දත්තවල සියලු දෙනාම අවම වශයෙන් එක් වරක්වත් ඇණවුම් කර ඇති නිසා)
```

## අභ්‍යාසය 4: උසස් ප්‍රශ්න (අත්‍යවශ්‍ය නැත・කාලය ඉතිරි නම් උත්සාහ කරන්න)

අභ්‍යාසය 1〜3 කළ හැකි නම් අද දිනයේ ඉලක්කය සම්පූර්ණයි. අභ්‍යාසය 4 හි `HAVING` වැනි නව අන්තර්ගතයන් ඇතුළත් නිසා,
සියල්ලම විසඳීමට උත්සාහ කළ යුතුම නැත. (තවදුරටත්, පාඩම 09 හි ආරම්භක දත්ත පදනම් කරගෙන සිතන්න)

```sql
-- ① එක් පුද්ගලයෙකුගේ සාමාන්‍ය මිලදී ගැනීමේ මුදල වැඩිම පරිශීලකයා සොයන්න
--    අපේක්ෂිත ප්‍රතිදානය: 山田次郎 (සාමාන්‍යය යෙන් 98000. 田中太郎 යෙන් 52200, 鈴木花子 යෙන් 53250)

-- ② එක් එක් පරිශීලකයාගේ "නවතම ඇණවුම් දිනය සහ වේලාව" පෙන්වන්න
--    ඉඟිය: GROUP BY + MAX(ordered_at)
--    අපේක්ෂිත ප්‍රතිදානය: ආරම්භක දත්ත එක් INSERT එකකින් එකවර ලියාපදිංචි කළ නිසා, තිදෙනාටම එකම දිනය සහ වේලාව ලැබේ

-- ③ මුළු ඇණවුම් මුදල යෙන් 100000 හෝ ඊට වැඩි පරිශීලකයින්ගේ නම සහ ඊමේල් පෙන්වන්න
--    ඉඟිය: GROUP BY + HAVING SUM(...) >= 100000
--    (WHERE සහ HAVING අතර වෙනස සඳහා පාඩම් ද්‍රව්‍යයේ 7 වන පරිච්ඡේදයේ "HAVING" කොටස බලන්න)
--    අපේක්ෂිත ප්‍රතිදානය: 田中太郎(යෙන් 104400), 鈴木花子(යෙන් 106500) යන දෙදෙනා (山田次郎 යෙන් 98000 නිසා ඇතුළත් නොවේ)
```
