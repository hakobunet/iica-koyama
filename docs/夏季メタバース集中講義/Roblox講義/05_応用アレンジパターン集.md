# 応用アレンジパターン集

**`03`のコイン集めゲームを完成させたうえで、もっと難しい・凝ったゲームを作りたいチーム**向けの資料。`06_アイデア集.md`で紹介している企画（`01`〜`04`の範囲だけで作れるもの）では物足りない場合に、次のステップとして読むページになる。

想定用途：2日目3限以降、チームが企画を実装する段階で使う参考資料。`2日目/3限目.md`で紹介される4つの応用パターン（Obby化・鬼ごっこ化・ショップ化・脱出ゲーム化）について、**講師の説明がなくてもこのページだけを読んで実装できる**よう、手順とコードをまとめている。

**このページの位置づけ**：

| ページ | 難易度 | 内容 |
|---|---|---|
| `03`コードスニペット集 | 必須 | 全員が最初に作る、基本のコイン集めゲーム |

## 1. Obby化（障害物コース・チェックポイント）

コインを「チェックポイント」に置き換え、触れるとそこが復活地点になる仕組み。落下やトラップで倒れても、最初からではなく直前のチェックポイントから再開できるようにする。

### 作りたいものの流れ
1. コースの要所要所にチェックポイントパーツを置く
2. プレイヤーがチェックポイントに触れると、そこが「復活地点」として記録される
3. プレイヤーが落下などでキャラクターが倒れると、記録された地点から再スタートする

### 手順

1. コースに沿って、目印になるパーツ（例：旗や台の形）を複数配置する（`01`の3章参照）
2. 1つ目のチェックポイントパーツを選択し、Propertiesの`Name`を`Checkpoint1`にする
3. `Checkpoint1`に`Script`を挿入し、以下を入力する

```lua
local checkpoint = script.Parent

checkpoint.Touched:Connect(function(hit)
    local player = game.Players:GetPlayerFromCharacter(hit.Parent)

    if player then
        player.RespawnLocation = checkpoint
    end
end)
```

4. 同じスクリプトを他のチェックポイントにもコピーする（パーツごと`Ctrl+D`で複製すれば、中のスクリプトも一緒に複製される。名前だけ`Checkpoint2`、`Checkpoint3`…と変えていく）
5. Playモードで、チェックポイントに触れてからわざと落下（またはキャラクターを倒す）し、直前のチェックポイントから復活することを確認する

- **コードの意味**：`Player.RespawnLocation`は「このプレイヤーが次に復活する場所」を指定するRobloxの標準機能。触れたチェックポイントのパーツをそのまま代入するだけで、次回の復活地点として登録される
- **よくあるエラー**：チェックポイントのパーツの`Anchored`がオフだと、パーツ自体が落下してしまい機能しなくなる。`Anchored`は必ずオンにする（`01`の7章参照）
- **発展**：落下したら即座にキャラクターを倒すための「落下エリア」を作りたい場合、コース下に大きな透明パーツを置き、以下のスクリプトを挿入する

```lua
local killZone = script.Parent

killZone.Touched:Connect(function(hit)
    local character = hit.Parent
    local humanoid = character:FindFirstChild("Humanoid")

    if humanoid then
        humanoid.Health = 0
    end
end)
```

`humanoid.Health = 0`でキャラクターの体力を0にすると、そのキャラクターは倒れて、直前のチェックポイントから自動的に復活する（`Health`の基本的な扱い方は`02`の8-4章参照）。

## 2. 鬼ごっこ化（オニが触れると交代）

1人が「オニ」となり、他のプレイヤーに触れると「オニ」の役割が入れ替わる仕組み。

### 作りたいものの流れ
1. ゲーム開始時、1人がオニになり、キャラクターの色が変わる
2. オニが他のプレイヤーに触れると、オニの役割が相手に移る（色も入れ替わる）
3. タッチされた直後に連続でオニが入れ替わらないよう、少し間隔を空ける

### 手順

1. `ServerScriptService`に新しい`Script`を挿入する（名前は`OniGame`など）
2. 以下を入力する

```lua
local Players = game:GetService("Players")

local oniPlayer = nil
local tagCooldown = false

local function paintCharacter(character, color)
    for _, part in ipairs(character:GetDescendants()) do
        if part:IsA("BasePart") then
            part.Color = color
        end
    end
end

local function setOni(player)
    oniPlayer = player
    if player.Character then
        paintCharacter(player.Character, Color3.fromRGB(255, 0, 0))
    end
end

local function setupCharacter(player, character)
    if player == oniPlayer then
        paintCharacter(character, Color3.fromRGB(255, 0, 0))
    end

    for _, part in ipairs(character:GetDescendants()) do
        if part:IsA("BasePart") then
            part.Touched:Connect(function(hit)
                if tagCooldown then return end
                -- このTouchedはオニ自身の体にも仕掛けているため、オニ以外の体が触れられたケースはここで無視する
                if player ~= oniPlayer then return end

                local otherPlayer = Players:GetPlayerFromCharacter(hit.Parent)

                if otherPlayer and otherPlayer ~= oniPlayer then
                    paintCharacter(oniPlayer.Character, Color3.fromRGB(255, 255, 255))
                    tagCooldown = true
                    setOni(otherPlayer)
                    task.wait(2)
                    tagCooldown = false
                end
            end)
        end
    end
end

Players.PlayerAdded:Connect(function(player)
    if oniPlayer == nil then
        setOni(player)
    end

    player.CharacterAdded:Connect(function(character)
        setupCharacter(player, character)
    end)
end)
```

3. このゲームは1人だけでは動作確認ができない（触れる相手がいないため）。画面上部のリボンメニューには「Home」「Model」などのタブが並んでいるが、その中から「Test」というタブを開く
4. 「Test」タブの中にある「Players」という項目（参加人数を選べるプルダウン）を探し、初期値の`1`から`2`以上に変更する
5. 「Test」タブの「Start」ボタン（または通常の「Play」ボタン）を押すと、指定した人数分のプレイヤーとして同時にテストプレイできる状態になる（複数のウィンドウが立ち上がり、それぞれ別々のプレイヤーとして操作できる）
6. 複数人分のウィンドウのうち1つを見て、最初の1人が赤くなっていることを確認する
7. 赤いプレイヤー（オニ）が別のウィンドウで操作しているプレイヤーに触れると、色が入れ替わることを確認する

- **コードの意味**：`oniPlayer`という変数で「今誰がオニか」を常に記録している。`paintCharacter`はキャラクターの全パーツの色を変える処理をまとめた関数。`tagCooldown`は「今タッチ判定を一時的に止めているか」のフラグで、これがないとタッチした瞬間に何度も入れ替わってしまう
- **よくあるエラー**：1人だけでPlayモードのテストプレイをすると、そもそも触れる相手がいないため動作確認ができない。上記の「Test」タブの手順で参加人数を2以上に増やしてからテストする
- **発展**：オニに触れられたら一定時間動けなくする（`Humanoid.WalkSpeed`を一時的に0にする）などのアレンジもしやすい

## 3. ショップ化（コインを通貨にしてアイテムを買う）

集めたスコアを通貨として消費し、アイテムや効果と交換する仕組み。「ボタンを押して購入」ではなく、Robloxで標準的な「近づいてEキーを押す」という購入UI（ProximityPrompt）を使う。

### 作りたいものの流れ
1. お店のパーツを1つ設置する
2. プレイヤーが近づくと「購入する（Eキー）」という表示が自動で出る
3. Eキーを押すと、スコアが足りていれば代金を消費し、効果（例：移動速度アップ）を得る

### 手順

1. Viewportにお店の目印になるパーツを1つ配置する
2. そのパーツに`Script`を挿入し、以下を入力する

```lua
local shopPart = script.Parent

local prompt = Instance.new("ProximityPrompt")
prompt.ActionText = "購入する"
prompt.ObjectText = "スピードアップ（10コイン）"
prompt.Parent = shopPart

local PRICE = 10

prompt.Triggered:Connect(function(player)
    local score = player.leaderstats.Score

    if score.Value >= PRICE then
        score.Value = score.Value - PRICE
        player.Character.Humanoid.WalkSpeed = 32
    end
end)
```

3. Playモードで、コインをいくつか集めた状態でお店のパーツに近づく
4. 「購入する」という表示が自動で出ることを確認し、Eキーを押す
5. スコアが10以上減り、移動速度が上がることを確認する

- **コードの意味**：`Instance.new("ProximityPrompt")`で、近づくと自動的に表示される購入UIを生成している。`Triggered`イベントは「プレイヤーが実際にEキーを押した瞬間」に発生する。押された瞬間にスコアを確認し、足りていれば代金を引いて効果を与える
- **よくあるエラー**：スコアが足りないのに効果が発動しない、という動作は正しい仕様（`if score.Value >= PRICE then`の中でしか処理が実行されないため）。「反応しない＝バグ」ではなく「お金が足りていない」の可能性をまず疑う
- **発展**：`WalkSpeed`の代わりに`JumpHeight`（ジャンプの高さ、`02`の8-5章参照）を変えたり、`Instance.new("Tool")`でアイテムを渡したりと、購入後の効果はアレンジ次第で自由に変えられる

## 4. 脱出ゲーム化（鍵アイテムでドアを開ける）

コインを「鍵」に置き換え、鍵を持っているプレイヤーだけがドアを通れるようにする仕組み。

### 作りたいものの流れ
1. 鍵のパーツに触れると、そのプレイヤーが「鍵を持っている」状態になる
2. ドアのパーツに触れたとき、鍵を持っていればドアが開く（通れるようになる）

### 手順

1. 鍵の目印になるパーツを1つ配置し、`Script`を挿入して以下を入力する

```lua
local key = script.Parent

key.Touched:Connect(function(hit)
    local player = game.Players:GetPlayerFromCharacter(hit.Parent)

    if player then
        player:SetAttribute("HasKey", true)
        key:Destroy()
    end
end)
```

2. ドアの役割になるパーツを1つ配置し、`Script`を挿入して以下を入力する

```lua
local door = script.Parent

door.Touched:Connect(function(hit)
    local player = game.Players:GetPlayerFromCharacter(hit.Parent)

    if player and player:GetAttribute("HasKey") then
        door.Transparency = 1
        door.CanCollide = false
    end
end)
```

3. Playモードで、鍵を取らずにドアに触れても何も起きないことを確認する
4. 鍵を取ってからドアに触れると、ドアが透明になり通り抜けられるようになることを確認する

- **コードの意味**：`SetAttribute("HasKey", true)`は、そのプレイヤーに「HasKeyという名前の情報」を付けておく仕組み（Robloxの「Attribute（属性）」という機能）。ドア側は`GetAttribute("HasKey")`でその情報を確認し、`true`であれば透明化＋すり抜け可能にしている
- **よくあるエラー**：鍵を取る前にドアが最初から開いている場合、ドアパーツの初期状態（`Transparency`や`CanCollide`）を確認する。最初は`Transparency = 0`・`CanCollide = true`（閉まった状態）にしておく必要がある
- **発展**：鍵を複数種類用意し、`SetAttribute("HasKeyA", true)`のように名前を変えて複数の鍵とドアの組み合わせを作ることもできる

## どのパターンを選ぶか迷ったら

`06`のアイデアだけでは物足りない、という場合にここから1つ選ぶとよい。

| やりたいこと | 選ぶパターン |
|---|---|
| プレイヤー同士のスキル・操作の上手さを競わせたい | Obby化 |
| プレイヤー同士が絡み合う対人要素を入れたい | 鬼ごっこ化 |
| 集めた要素を「使う」楽しさを入れたい | ショップ化 |
| 謎解き・探索の要素を入れたい | 脱出ゲーム化 |

いずれのパターンも、`03`で作ったleaderstats・Touchedイベント・Script/LocalScriptの基本構造をそのまま土台にしている。新しい技術要素（`RespawnLocation`・`Touched`によるHealth操作・`ProximityPrompt`・`Attribute`）はそれぞれ1つずつしか登場しないため、必要なパターンの章だけを読めば実装できる。

## 5.（参考）講義では扱わないが使えるスクリプト

ここから先は標準の講義では説明しないが、企画によっては使いたくなるかもしれない発展的なスクリプト。時間に余裕があるチームや、興味を持った人向けの参考資料として置いている。

### 5-1. 手に持つ道具を作る（Tool）

これまでの仕組みはすべて「パーツに触れる」ことで発動していたが、Robloxには「手に持って使う」道具（`Tool`）という仕組みもある。剣・杖・懐中電灯・鍵など、プレイヤーが選んで使うアイテムを作りたい場合に使う。

### 作りたいものの流れ
1. 手に持てる道具（例：回復の杖）を1つ用意する
2. プレイヤーがその道具を装備すると、手に持った状態で表示される
3. クリック（またはコントローラーのボタン）を押すと、道具固有の効果（今回は「持っている本人の体力を回復する」）が発動する

### 手順

1. Explorerで`StarterPack`を右クリック→「Insert Object」→`Tool`を挿入する（`StarterPack`に置いたものは、ゲーム開始時に全プレイヤーのBackpack（インベントリ）に自動的に配られる）
2. 挿入した`Tool`のPropertiesパネルで`Name`を`HealWand`に変更する
3. `HealWand`を右クリック→「Insert Object」→`Part`を挿入し、`Name`を`Handle`に変更する（**`Handle`という名前は必須**。これがないと道具として認識されず、手に持っても何も表示されない）
4. `Handle`のSizeを調整し、杖らしい細長い形にする（`01`の3-3章参照）
5. `HealWand`（Toolオブジェクト自身）を右クリック→「Insert Object」→`Script`を挿入する
6. エディタに以下を入力する

```lua
local tool = script.Parent

tool.Activated:Connect(function()
    local character = tool.Parent
    local humanoid = character and character:FindFirstChild("Humanoid")

    if humanoid then
        humanoid.Health = humanoid.MaxHealth
    end
end)
```

7. Playモードに入り、画面下部のBackpackから`HealWand`をクリックして装備する
8. 装備した状態で左クリック（またはタップ）すると、体力が全回復することを確認する

- **コードの意味**：`tool.Activated`は、道具を装備した状態でクリック（またはタップ）した瞬間に発生するイベント。`tool.Parent`は、道具を装備している間は「持っているプレイヤーのキャラクター」を指す（Backpackに入っている装備前の状態では、`tool.Parent`はキャラクターではなくBackpack自身になる）
- **どこで使うか**：`Handle`という名前のPartを1つ持たせ、`Activated`イベントに処理を書く、という2点がToolの基本形。効果の中身を`02`の8-4〜8-6章（Health・JumpHeight・WalkSpeed）や8-3（TakeDamage）に差し替えれば、回復の杖以外にも「攻撃の剣」「ジャンプ力アップの靴」などに応用できる
- **よくあるエラー**：`Handle`という名前のPartを用意し忘れると、道具が正しく手に表示されない（見えない・持てない）。名前のスペルミスが最頻出
- **発展**：装備している間だけ効果を出し続けたい場合（例：装備中だけ`WalkSpeed`が上がる靴）は、`tool.Equipped`（装備した瞬間）と`tool.Unequipped`（外した瞬間）の2つのイベントを使い、`Equipped`で効果を適用、`Unequipped`で元に戻す、という組み合わせにする

### 5-2. チームに分ける（Teams）

`2章`の鬼ごっこでは「オニかどうか」を変数で管理し、色を手動で塗り替えていたが、Robloxには`Team`というプレイヤーをグループ分けするための標準機能がある。チーム対抗のPvP・陣取り・旗取りゲームなどを作りたい場合の土台になる。

### 作りたいものの流れ
1. あらかじめ複数のチーム（例：Red Team・Blue Team）を用意しておく
2. プレイヤーが参加すると、人数の少ない方のチームに自動的に振り分けられる
3. チームに入ると、そのチームカラーでキャラクターが表示される

### 手順

1. Explorerで`Teams`（サービスの1つ。`ServerScriptService`などと同じ階層にある）を右クリック→「Insert Object」→`Team`を挿入する。これを2つ作る
2. 1つ目の`Team`のPropertiesパネルで`Name`を`Red Team`に、`TeamColor`を`Bright red`に変更する
3. 2つ目の`Team`は`Name`を`Blue Team`に、`TeamColor`を`Bright blue`に変更する
4. `ServerScriptService`に新しい`Script`を挿入し、以下を入力する

```lua
local Teams = game:GetService("Teams")
local Players = game:GetService("Players")

local function paintCharacter(character, color)
    for _, part in ipairs(character:GetDescendants()) do
        if part:IsA("BasePart") then
            part.Color = color
        end
    end
end

Players.PlayerAdded:Connect(function(player)
    local redTeam = Teams:FindFirstChild("Red Team")
    local blueTeam = Teams:FindFirstChild("Blue Team")

    if #redTeam:GetPlayers() <= #blueTeam:GetPlayers() then
        player.Team = redTeam
    else
        player.Team = blueTeam
    end

    player.CharacterAdded:Connect(function(character)
        paintCharacter(character, player.Team.TeamColor.Color)
    end)
end)
```

5. Playモードで、複数人（`2章`の鬼ごっこと同様、「Test」タブから「Players」の人数を2以上に増やして確認する）参加させ、それぞれ`Red Team`・`Blue Team`のチームカラーでキャラクターが表示されることを確認する

- **コードの意味**：`redTeam:GetPlayers()`・`blueTeam:GetPlayers()`は、それぞれのチームに今何人いるかを配列（テーブル）として取得する。その人数（`#`をつけると要素数が分かる）を比べ、少ない方に`player.Team`を代入することで、人数のバランスを取っている。`paintCharacter`関数は`2章`の鬼ごっこと同じもので、`player.Team.TeamColor.Color`（そのプレイヤーのチームカラー）でキャラクター全体を塗っている
- **どこで使うか**：チーム対抗のPvP・陣取り・旗取りゲームなど、複数人vs複数人の対人企画全般の土台
- **よくあるエラー**：`Team`の`Name`（`"Red Team"`など）のスペルミスが最頻出。`FindFirstChild`で`nil`が返っている場合、まずここを疑う
- **発展**：個人のスコア（`leaderstats`）とは別に「チーム合計スコア」を表示したい場合、そのチームに所属する全プレイヤーの`Score`を`GetPlayers()`でループしながら合計する処理を書けばよい

### 5-3. 離れたスイッチでドアを開ける（ClickDetector）

`4章`の鍵は「パーツに触れる」ことで取得する仕組みだったが、`ClickDetector`を使うと「離れた場所からマウスでクリックする」操作の仕掛けが作れる。レバー・ボタン・スイッチなど、触れるのではなく意図的に操作するタイプの謎解き要素に使う。

### 作りたいものの流れ
1. スイッチ役のパーツを1つ用意する
2. プレイヤーがそのパーツをクリックすると、対応するドアが開く

### 手順

1. スイッチにしたいパーツを1つ配置し、`Name`を`Switch`に変更する
2. `Switch`を右クリック→「Insert Object」→`ClickDetector`を挿入する（これを付けたパーツだけが、マウスでクリックできる対象になる）
3. ドアの役割になるパーツを1つ配置し、`Name`を`Door`に変更する（`Transparency`は`0`、`CanCollide`は`true`にしておく）
4. `Switch`に`Script`を挿入し、以下を入力する

```lua
local switchPart = script.Parent
local clickDetector = switchPart.ClickDetector
local door = workspace:WaitForChild("Door")

clickDetector.MouseClick:Connect(function(player)
    door.Transparency = 1
    door.CanCollide = false
end)
```

5. Playモードで、`Switch`パーツをマウスでクリックすると`Door`が透明になり、通り抜けられるようになることを確認する

- **コードの意味**：パーツに`ClickDetector`を追加すると、そのパーツはマウスでクリック（またはタップ）できる対象になる。`MouseClick`イベントは実際にクリックされた瞬間に発生し、クリックしたプレイヤー自身が引数（`player`）として渡される
- **どこで使うか**：`Touched`（触れる）ではなく、プレイヤーが意図的にクリックして操作するタイプの仕掛け全般（レバー・ボタン・スイッチなど）
- **よくあるエラー**：`ClickDetector`の`MaxActivationDistance`（デフォルトは32スタッド）より遠くにいるとクリックしても反応しない。離れた場所からでも押せるようにしたい場合はこの数値を大きくする
- **発展**：複数のスイッチを正しい順番で押さないと開かない、といった謎解きにしたい場合は、押された順番を記録するテーブルを用意し、正しい並びと一致するかどうかを確認する処理を足すとよい
