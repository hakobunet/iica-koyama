# 企画アイデア集

想定用途：2日目3限以降、チームで企画を決める段階の参考資料。`01`〜`03`で学んだ要素だけを組み合わせて、どんなゲームが作れるかの具体例を集めている（`04`で扱う応用パターンは含まない）。

**使い方**：ここに載っているものをそのまま作ってもよいし、複数のアイデアを混ぜたり、自分たちの発想で新しい要素を足したりしてもよい。各アイデアの「使う要素」に書かれた章を読めば、実装に必要な知識はすべて揃っている。

## 1. コイン集めタイムアタック

`03`で作ったコイン集めゲームそのものを、そのまま1つの企画として仕上げるアイデア。新しいコードはほぼ不要で、コースデザインに時間をかけられる。

- **概要**：コインの配置場所や数を工夫し、「全部集めるまでの速さ」を競うゲームにする
- **使う要素**：
  - コインに触れると消える・スコア加算（`03`のB・D）
  - leaderstats・自作GUIでのスコア表示（`03`のC・E）
  - 全部集めたときのクリア通知（`03`のF・G）
- **実装のヒント**：コードは`03`のままでよいので、コインを隠す場所・数・コースの見た目（`01`の3〜6章）に力を入れると企画としての完成度が上がる
- **難易度の目安**：★☆☆（`03`をそのまま使うだけで形になる）

## 2. ランダム降下チャレンジ

`02`の8-2章で紹介した「ランダムにパーツを複製して降らせる」仕組みをベースにしたゲーム。

- **概要**：安全なパーツと危険なパーツがランダムに降ってくる中、危険な方（ダメージパーツ）を避けながら生き残る、またはできるだけ多く安全なパーツに触れてスコアを稼ぐ
- **使う要素**：
  - ServerStorageからのランダム複製（`02`の8-2章）
  - 触れたらダメージ（`02`の8-3章）
  - スコア表示（`03`のC・D・E）
- **実装のヒント**：`02`の8-2章のコードにある「安全なパーツ（`NormalPart`）」に触れたときの処理として、`03`のコインと同じようにスコアを1増やす処理を足すだけで、そのままゲームとして成立する
- **難易度の目安**：★★☆（8-2章の複製処理とスコア加算を自分たちで組み合わせる必要がある）

## 3. 動く床サバイバル

`02`の8-1章で紹介した「動き続けるパーツ」の上に乗り続け、どれだけ長く落ちずにいられるかを競うゲーム。

- **概要**：一定方向に動き続ける床（コンベア・上下する足場など）の上でバランスを取り、下に落ちたらダメージを受ける、または即座に脱落とする
- **使う要素**：
  - 動き続けるパーツ（`02`の8-1章）
  - 落ちたらダメージを与える仕組み（`02`の8-3章、床の下に大きな透明パーツを置いて使う）
  - 生存時間をスコアとして数える場合は`03`のleaderstatsの仕組みを応用
- **実装のヒント**：生存時間をスコアにしたい場合、`while true do ... task.wait(1) ... score.Value = score.Value + 1 ... end`のように、1秒ごとにスコアを1ずつ増やすループを書くと「長く生き残るほど得点が増える」仕組みになる
- **難易度の目安**：★★☆（動くパーツとダメージ判定を組み合わせ、生存時間のスコア化は自分たちで考える部分がある）

## 4. 回復アイテム争奪サバイバル

ダメージゾーンが点在するコースの中で、体力を回復するパーツを取り合いながら生き残るゲーム。

- **概要**：コース上に複数のダメージトラップを置き、同時に体力回復パーツも配置する。プレイヤーはダメージを受けつつ回復パーツを取りながら、できるだけ長く・遠くまで進む
- **使う要素**：
  - 触れたらダメージ（`02`の8-3章）
  - 触れたら体力回復（`02`の8-4章）
  - スコア表示（`03`のC・D・E、進んだ距離や生存時間をスコアにする）
- **実装のヒント**：回復パーツは`03`のコインと同じ「触れたら`Destroy()`」の考え方を使い、`Destroy()`の前に`humanoid.Health = humanoid.MaxHealth`を実行する処理を足せばよい
- **難易度の目安**：★★☆（ダメージ・回復・スコアの3つを1つのコースの中で組み合わせる）

## 5. 隠しコインの宝探し

`03`のコイン集めゲームを、見つけにくい場所にコインを隠す「宝探し」として作り直すアイデア。

- **概要**：見つけにくい場所（物陰・高い場所・遠い場所など）に複数のコインを隠し、全部集めるとクリア。コードはほとんど変更せず、コース・レベルデザインの工夫だけで難易度を作る
- **使う要素**：
  - コインとスコア（`03`のB〜E）
  - クリア通知（`03`のF・G）
- **実装のヒント**：コード面での新しい要素はほとんど不要なため、企画・レベルデザイン重視のチームに向いている
- **難易度の目安**：★☆☆（コードよりも配置・謎解き設計に時間がかかる）

## 6. スピード変化コース

`02`の8-6章で紹介した「触れると移動速度が変わるパーツ」を使った、駆け引きのあるコース。

- **概要**：コースの一部に「速度が上がるパーツ」「速度が下がるパーツ」を混ぜて配置し、どのルートを通ると速くゴールできるかを考えさせるタイムアタック
- **使う要素**：
  - 移動速度を変える（`02`の8-6章。上げる場合は`originalSpeed * 2`のような数値を、下げる場合は`originalSpeed / 2`のような数値にする）
  - スコア表示（`03`のC・D・E、クリアタイムや到達順をスコアにする）
- **実装のヒント**：`02`の8-6章のコードの数値（`32`の部分）を場所によって変えるだけで、「速くなるパーツ」と「遅くなるパーツ」の両方を作れる
- **難易度の目安**：★☆☆（`02`の8-6章のコードをそのまま複製して数値を変えるだけで作れる）

## 7. みんなで建築イベント

スクリプトを使わず、`01`のTeam Create機能だけを使った共同制作企画。

- **概要**：チーム全員で1つの空間に同時に入り、街・建物・世界観などをみんなで作り上げる。完成後、その空間の中で`03`のコイン集めゲームを遊べるようにすると、制作物と遊びを両立できる
- **使う要素**：
  - Team Create（`01`の9章）
  - パーツの配置・編集・グループ化（`01`の3〜6章）
- **実装のヒント**：役割分担（地形担当・建物担当・装飾担当など）を決めてから始めると、同時編集での作業がぶつかりにくい
- **難易度の目安**：★☆☆（コードを使わないため、プログラミングが苦手なチームでも取り組みやすい）

## 企画を決めるときの考え方

- 難易度は目安であり、チームの人数やスキルに応じて要素を減らして調整してよい（例：4の回復アイテム争奪から回復パーツを外し、ダメージ回避だけのシンプルなゲームにする、など）
- 複数のアイデアを組み合わせることもできる（例：2のランダム降下チャレンジ＋6のスピード変化パーツ、など）
- ここに載っているのは`01`〜`03`の範囲でできることの一部にすぎない。時間や興味に応じて、自分たちなりのアレンジを加えてよい
