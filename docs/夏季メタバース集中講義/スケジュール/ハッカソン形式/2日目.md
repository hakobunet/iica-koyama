#### 10:40-10:50｜導入（10分）

#### 10:50-11:05｜Lua基本文法の確認（15分）
- PHPとの対比で説明：
  - 変数：`local score = 0`（PHPの`$score = 0;`相当）
  - if文／for文：構文は違うが考え方は同じ
  - 関数：`local function foo() end`（PHPの`function foo() {}`相当）
- 注意点：文法の細かい暗記より「知ってる概念の言い換え」であることを強調し、安心させる

#### 11:05-11:25｜Script／LocalScriptの違い（20分）
- 話すポイント（PHP/Laravelのアナロジー）：
  - **Script＝サーバー側で動く**＝Laravelのコントローラー・処理と同じ立ち位置。全プレイヤー共通の処理（スコア計算、アイテム管理など）はここに書く
  - **LocalScript＝各プレイヤーの画面側だけで動く**＝Bladeで出したHTMLをJSで動かす部分に近い。画面表示・演出はここに書く
  - 「サーバーで確定させたい処理はScript、見た目だけの処理はLocalScript」という判断基準を提示
- 進行手順：Explorer上でScriptとLocalScriptをそれぞれ挿入し、Outputに`print`で違いを確認させる（LocalScriptはクライアント側でしか実行されないことを、複数人が同じPlaceに入った状態で見せると分かりやすい）

#### 11:25-11:50｜コインパーツ作成＋Touchedイベント実装（25分）
- 進行手順：
  1. 黄色い円柱パーツを1つ配置し、名前を`Coin`にする
  2. `Coin`に`Script`を挿入し、以下を入力・実行

     ```lua
     local coin = script.Parent

     coin.Touched:Connect(function(hit)
         local character = hit.Parent
         local player = game.Players:GetPlayerFromCharacter(character)

         if player then
             coin:Destroy()
         end
     end)
     ```

  3. Playモードでコインに触れると消えることを確認
- 話すポイント：`hit.Parent`からプレイヤーを特定する処理は「誰が触れたか」を判定する、Robloxでは頻出のパターンであることを説明

#### 11:50-12:05｜leaderstatsでスコア加算（15分）
- 進行手順：
  1. `ServerScriptService`に新しい`Script`を追加し、プレイヤー参加時にスコア（`leaderstats`）を作成する処理を実装

     ```lua
     local Players = game:GetService("Players")

     Players.PlayerAdded:Connect(function(player)
         local leaderstats = Instance.new("Folder")
         leaderstats.Name = "leaderstats"
         leaderstats.Parent = player

         local score = Instance.new("IntValue")
         score.Name = "Score"
         score.Value = 0
         score.Parent = leaderstats
     end)
     ```

  2. 先ほどのコインのスクリプトに、スコア加算処理を追記

     ```lua
     if player then
         player.leaderstats.Score.Value = player.leaderstats.Score.Value + 1
         coin:Destroy()
     end
     ```

  3. Playモードで、コインに触れるたびに右上のリーダーボードのスコアが増えることを確認
- 話すポイント：「`game:GetService("Players")`は、PHPで言えば必要な機能を呼び出す感覚に近い」とアナロジーで補足

#### 12:05-12:10｜まとめ・2限予告（5分）
- 「次の2限では、このスコアを自分たちのGUI（画面）に表示し、コインを全部集めたら“クリア”と出す仕組みを作ります」

### トラブルシューティング／注意点
- **`Touched`が反応しない**：パーツの`CanCollide`がオフになっていないか確認。プレイヤーキャラクターがすり抜けている場合が多い
- **`player`が`nil`になる**：Toolboxの既存アセットなど、プレイヤー以外（他のパーツ）がコインに触れた場合。`if player then`のガード節がその対策であることを説明
- **スコアが表示されない**：`leaderstats`という名前のスペルミスが最多。Explorerで実際にツリーを確認させる

### 詳細進行

#### 10:40-10:50｜導入（10分）
- 話すポイント：「1限で作ったスコアは、実はRobloxの標準リーダーボードに自動で出ていました。今回は、自分たちのオリジナルGUIでそれを表示する方法をやります」
- 完成イメージ（画面左上にオリジナルのスコア表示、コイン全部集めたら中央に“クリア！”のメッセージ）を見せる

#### 10:50-11:15｜GUIでスコア表示（25分）
- 進行手順：
  1. `StarterGui`に`ScreenGui`を挿入し、その中に`TextLabel`を配置
  2. `TextLabel`に`LocalScript`を挿入し、以下を実装

     ```lua
     local player = game.Players.LocalPlayer
     local label = script.Parent

     local function updateScore()
         label.Text = "Score: " .. player.leaderstats.Score.Value
     end

     player.leaderstats.Score:GetPropertyChangedSignal("Value"):Connect(updateScore)
     updateScore()
     ```

  3. Playモードでコインを集めると、自作のGUI表示が更新されることを確認
- 話すポイント（アナロジー）：「`LocalPlayer`は、Laravelでいう“今ログイン中のユーザー”（`Auth::user()`）に近い感覚。自分の画面にしか関係ない情報はLocalScriptで扱う」

#### 11:15-11:45｜RemoteEventでクリア通知（30分）
- 進行手順：
  1. `ReplicatedStorage`に`RemoteEvent`を1つ作成し、名前を`GameCleared`にする
  2. サーバー側（`ServerScriptService`のScript）に、コインが全部なくなったら`GameCleared`を発火する処理を追加

     ```lua
     local ReplicatedStorage = game:GetService("ReplicatedStorage")
     local gameClearedEvent = ReplicatedStorage:WaitForChild("GameCleared")

     -- コインを数える処理（例：Workspace内のCoinという名前のパーツをカウント）
     local function checkClear(player)
         local coinsLeft = 0
         for _, obj in ipairs(workspace:GetChildren()) do
             if obj.Name == "Coin" then
                 coinsLeft += 1
             end
         end
         if coinsLeft == 0 then
             gameClearedEvent:FireClient(player)
         end
     end
     ```

  3. クライアント側（`StarterGui`配下の`LocalScript`）で、通知を受け取ったら「クリア！」のGUIを表示

     ```lua
     local ReplicatedStorage = game:GetService("ReplicatedStorage")
     local gameClearedEvent = ReplicatedStorage:WaitForChild("GameCleared")

     gameClearedEvent.OnClientEvent:Connect(function()
         script.Parent.ClearedLabel.Visible = true
     end)
     ```

- 話すポイント（アナロジー）：「`FireClient`はLaravelでいうAjaxのレスポンスをフロントに返すイメージ。サーバーで判定→クライアントに“結果だけ”伝える、という役割分担はWeb開発と同じ発想」
- 注意点：ここが今日いちばんの難所。エラーが出ても「サーバー側とクライアント側、両方に書く」という基本構造さえ掴めればOKとハードルを下げる

#### 11:45-12:00｜演習：自由にアレンジ（15分）

- AIツール（ChatGPT等）を使い、「このスクリプトに◯◯の機能を追加して」と依頼する体験もここで軽く紹介

#### 12:00-12:10｜まとめ・3限予告（10分）
- 話すポイント：
  - 「これで“コインを集めてクリアする”という、ゲームの基本骨格が全員の手元にできました」
  - 「次の3限からは、これを自分たちのチームの企画に合わせて改造していきます」
  - **「1つのコアメカニクスに絞ること」を予告として一言伝えておく**（3限の企画会議で改めて強調する）

### トラブルシューティング／注意点
- **GUIのTextLabelが更新されない**：`GetPropertyChangedSignal`の対象プロパティ名のスペルミスが多い（`"Value"`）
- **RemoteEventが反応しない**：`ReplicatedStorage`に作成したRemoteEvent名と、Script側・LocalScript側で参照している名前が一致しているか確認（最頻出ミス）
- **`FireClient`と`FireServer`を混同する**：「サーバー→クライアントは`FireClient`」「クライアント→サーバーは`FireServer`」を対で覚えさせる
