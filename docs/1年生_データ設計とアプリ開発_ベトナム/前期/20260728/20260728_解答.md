# Buổi 10 Bài tập｜Đáp án mẫu

> 🇯🇵 Bản gốc (tiếng Nhật): [20260728_解答.md](<../../../1年生_データ設計とアプリ開発/前期/20260728/20260728_解答.md>) <!-- original-ja-link -->

Đây là đáp án mẫu dựa trên dữ liệu ban đầu của users / products / orders trong `school_db` (xem tài liệu Buổi 09).
Nếu không có ghi chú gì đặc biệt, Bài tập 1, Bài tập 3 và Bài tập 4 lấy "dữ liệu ban đầu trước khi chạy Bài tập 2" làm chuẩn
(Bài tập 2 được xem là một chuỗi thao tác liên tiếp, chạy theo thứ tự ① → ⑤).

```
Bảng users (dữ liệu ban đầu)
id │ name     │ email
───┼──────────┼────────────────────
 1 │ 田中太郎 │ tanaka@example.com
 2 │ 鈴木花子 │ suzuki@example.com
 3 │ 山田次郎 │ yamada@example.com

Bảng products (dữ liệu ban đầu)
id │ name       │ price
───┼────────────┼───────
 1 │ ノートPC   │ 98000
 2 │ マウス     │  3200
 3 │ キーボード │  8500

Bảng orders (dữ liệu ban đầu)
id │ user_id │ product_id │ quantity
───┼─────────┼────────────┼─────────
 1 │    1    │     1      │    1     -- 田中太郎: ノートPC ×1
 2 │    1    │     2      │    2     -- 田中太郎: マウス ×2
 3 │    2    │     3      │    1     -- 鈴木花子: キーボード ×1
 4 │    3    │     1      │    1     -- 山田次郎: ノートPC ×1
 5 │    2    │     1      │    1     -- 鈴木花子: ノートPC ×1
```

---

## Bài tập 1: SELECT cơ bản

### ①

```sql
SELECT * FROM orders;
```

**Kết quả (tham khảo):** 5 hàng dữ liệu ban đầu ở trên được hiển thị nguyên vẹn (`ordered_at` chứa ngày giờ tại thời điểm INSERT).

### ②

```sql
SELECT * FROM products WHERE price >= 5000;
```

**Kết quả (tham khảo):**

| name | price |
|------|-------|
| ノートPC | 98000 |
| キーボード | 8500 |

マウス (3200 yên) có giá dưới 5000 yên nên không có trong kết quả.

### ③

```sql
SELECT * FROM users ORDER BY id DESC;
```

**Kết quả (tham khảo):** Hiển thị theo thứ tự 山田次郎(id=3) → 鈴木花子(id=2) → 田中太郎(id=1).

### ④

```sql
SELECT MAX(price) AS 最高額, MIN(price) AS 最安値 FROM products;
```

**Kết quả (tham khảo):** 最高額 (giá cao nhất) = 98000 (ノートPC), 最安値 (giá thấp nhất) = 3200 (マウス)

---

## Bài tập 2: INSERT / UPDATE / DELETE

### ①

```sql
INSERT INTO users (name, email) VALUES ('中村健二', 'nakamura@example.com');
```

**Kết quả (tham khảo):** "中村健二" được thêm vào với `id=4`.

### ②

```sql
INSERT INTO products (name, price) VALUES ('USBハブ', 2800);
```

**Kết quả (tham khảo):** "USBハブ" được thêm vào với `id=4`.

### ③

```sql
-- Trước tiên kiểm tra id
SELECT id FROM users WHERE name = '田中太郎';     -- → 1
SELECT id FROM products WHERE name = 'USBハブ';   -- → 4

-- Dùng id vừa kiểm tra để thêm đơn hàng
INSERT INTO orders (user_id, product_id, quantity) VALUES (1, 4, 3);
```

**Kết quả (tham khảo):** Dữ liệu "田中太郎 đặt mua 3 cái USBハブ" được thêm vào thành đơn hàng có `id=6`.

### ④

```sql
-- Kiểm tra trước
SELECT * FROM products WHERE name = 'ノートPC';

UPDATE products SET price = 95000 WHERE name = 'ノートPC';
```

**Kết quả (tham khảo):** Giá của ノートPC đổi từ 98000 yên → 95000 yên.

### ⑤

```sql
-- Vì có ràng buộc khóa ngoại nên xóa theo thứ tự orders → users
DELETE FROM orders
WHERE user_id = (SELECT id FROM users WHERE name = '中村健二');

DELETE FROM users WHERE name = '中村健二';
```

**Kết quả (tham khảo):** Trong bài tập này, 中村健二 chưa có đơn hàng nào được thêm, nên câu `DELETE` thứ nhất **tác động 0 hàng** (không có gì bị xóa = kết quả bình thường). Câu `DELETE` thứ hai xóa 中村健二(id=4).
Điểm mấu chốt là nếu cố xóa `users` trước thì sẽ bị lỗi do ràng buộc khóa ngoại (lần này 中村健二 thực tế không có đơn hàng nào nên không bị ảnh hưởng, nhưng thói quen giữ đúng thứ tự là rất quan trọng).

## Bài tập 3: JOIN và tổng hợp

### ①

```sql
SELECT
    users.name      AS ユーザー名,
    products.name   AS 商品名,
    orders.quantity AS 数量,
    products.price * orders.quantity AS 合計金額
FROM orders
INNER JOIN users    ON orders.user_id    = users.id
INNER JOIN products ON orders.product_id = products.id
ORDER BY orders.id;
```

**Kết quả (tham khảo):**

| ユーザー名 | 商品名 | 数量 | 合計金額 |
|---|---|---|---|
| 田中太郎 | ノートPC | 1 | 98000 |
| 田中太郎 | マウス | 2 | 6400 |
| 鈴木花子 | キーボード | 1 | 8500 |
| 山田次郎 | ノートPC | 1 | 98000 |
| 鈴木花子 | ノートPC | 1 | 98000 |

### ②

```sql
SELECT
    products.name   AS 商品名,
    orders.quantity AS 数量,
    products.price * orders.quantity AS 金額
FROM orders
INNER JOIN users    ON orders.user_id    = users.id
INNER JOIN products ON orders.product_id = products.id
WHERE users.name = '田中太郎';
```

**Kết quả (tham khảo):**

| 商品名 | 数量 | 金額 |
|---|---|---|
| ノートPC | 1 | 98000 |
| マウス | 2 | 6400 |

### ③

```sql
SELECT
    products.name AS 商品名,
    SUM(orders.quantity) AS 販売数量,
    SUM(products.price * orders.quantity) AS 売上合計
FROM orders
INNER JOIN products ON orders.product_id = products.id
GROUP BY products.id, products.name
ORDER BY 売上合計 DESC;
```

**Kết quả (tham khảo):**

| 商品名 | 販売数量 | 売上合計 |
|---|---|---|
| ノートPC | 3 | 294000 |
| キーボード | 1 | 8500 |
| マウス | 2 | 6400 |

### ④

```sql
SELECT users.name, users.email
FROM users
LEFT JOIN orders ON users.id = orders.user_id
WHERE orders.id IS NULL;
```

**Kết quả (tham khảo):** Trong dữ liệu ban đầu, cả 田中太郎, 鈴木花子 và 山田次郎 đều đã đặt hàng ít nhất 1 lần, nên **kết quả là 0 hàng**.
(Nếu tại thời điểm này bạn vẫn chưa xóa 中村健二 đã thêm ở Bài tập 2, thì chỉ có đúng 1 hàng là 中村健二 — người không có đơn hàng nào — được tìm thấy. Điểm mấu chốt của câu này là "không có người dùng nào có 0 đơn hàng = kết quả 0 hàng cũng là một kết quả đúng".)

## Bài tập 4: Bài nâng cao

### ①

```sql
SELECT
    users.name AS ユーザー名,
    AVG(products.price * orders.quantity) AS 平均購入金額
FROM orders
INNER JOIN users    ON orders.user_id    = users.id
INNER JOIN products ON orders.product_id = products.id
GROUP BY users.id, users.name
ORDER BY 平均購入金額 DESC
LIMIT 1;
```

**Kết quả (tham khảo):** Số tiền mua trung bình mỗi đơn hàng là: 田中太郎 = (98000+6400)/2 = 52200 yên, 鈴木花子 = (8500+98000)/2 = 53250 yên, 山田次郎 = 98000 yên (chỉ có 1 đơn hàng). Do đó **山田次郎 (98000 yên)** là cao nhất.

### ②

```sql
SELECT
    users.name AS ユーザー名,
    MAX(orders.ordered_at) AS 最新注文日時
FROM orders
INNER JOIN users ON orders.user_id = users.id
GROUP BY users.id, users.name;
```

**Kết quả (tham khảo):** Dữ liệu ban đầu được thêm cùng lúc bằng 1 câu lệnh `INSERT`, nên `ordered_at` của cả 3 người đều là cùng một ngày giờ tại thời điểm chạy lệnh. Nếu thêm đơn hàng vào những ngày khác nhau, bạn sẽ thấy "ngày giờ đặt hàng mới nhất" khác nhau theo từng người dùng.

### ③

```sql
SELECT
    users.name  AS ユーザー名,
    users.email AS メール
FROM orders
INNER JOIN users    ON orders.user_id    = users.id
INNER JOIN products ON orders.product_id = products.id
GROUP BY users.id, users.name, users.email
HAVING SUM(products.price * orders.quantity) >= 100000;
```

**Kết quả (tham khảo):**

| ユーザー名 | メール |
|---|---|
| 田中太郎 | tanaka@example.com |
| 鈴木花子 | suzuki@example.com |

Tổng số tiền mua của 田中太郎 là 104400 yên, của 鈴木花子 là 106500 yên, cả hai đều từ 100000 yên trở lên. 山田次郎 là 98000 yên nên không có trong kết quả.
