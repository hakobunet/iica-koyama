# Хичээл 10 Дасгал｜Хариуны жишээ

> 🇯🇵 Эх хувь (япон хэлээр): [20260728_解答.md](<../../../1年生_データ設計とアプリ開発/前期/20260728/20260728_解答.md>) <!-- original-ja-link -->

`school_db`-ийн users / products / orders хүснэгтүүдийн анхны өгөгдөлд (Хичээл 09-ийн материалыг үзнэ үү) үндэслэсэн хариуны жишээ.
Дасгал 1, Дасгал 3, Дасгал 4-ийг тусгайлан заагаагүй бол «Дасгал 2-ыг ажиллуулахаас өмнөх анхны өгөгдөл»-ийг үндэслэн бодно
(Дасгал 2-ыг ①→⑤ дарааллаар ажиллуулах, үргэлжилсэн үйлдэл гэж үзнэ).

```
users хүснэгт (анхны өгөгдөл)
id │ name     │ email
───┼──────────┼────────────────────
 1 │ 田中太郎 │ tanaka@example.com
 2 │ 鈴木花子 │ suzuki@example.com
 3 │ 山田次郎 │ yamada@example.com

products хүснэгт (анхны өгөгдөл)
id │ name       │ price
───┼────────────┼───────
 1 │ ノートPC   │ 98000
 2 │ マウス     │  3200
 3 │ キーボード │  8500

orders хүснэгт (анхны өгөгдөл)
id │ user_id │ product_id │ quantity
───┼─────────┼────────────┼─────────
 1 │    1    │     1      │    1     -- 田中太郎: ノートPC ×1
 2 │    1    │     2      │    2     -- 田中太郎: マウス ×2
 3 │    2    │     3      │    1     -- 鈴木花子: キーボード ×1
 4 │    3    │     1      │    1     -- 山田次郎: ノートPC ×1
 5 │    2    │     1      │    1     -- 鈴木花子: ノートPC ×1
```

## Дасгал 1: Үндсэн SELECT

### ①

```sql
SELECT * FROM orders;
```

**Үр дүн (лавлагаа):** Дээрх анхны өгөгдлийн 5 бичлэг тэр чигээрээ харагдана (`ordered_at`-д INSERT хийсэн агшны огноо, цаг орно).

### ②

```sql
SELECT * FROM products WHERE price >= 5000;
```

**Үр дүн (лавлагаа):**

| name | price |
|------|-------|
| ノートPC | 98000 |
| キーボード | 8500 |

マウス (3200 иен) нь 5000 иенээс бага тул хамаарахгүй.

### ③

```sql
SELECT * FROM users ORDER BY id DESC;
```

**Үр дүн (лавлагаа):** 山田次郎(id=3) → 鈴木花子(id=2) → 田中太郎(id=1) гэсэн дарааллаар харагдана.

### ④

```sql
SELECT MAX(price) AS 最高額, MIN(price) AS 最安値 FROM products;
```

**Үр дүн (лавлагаа):** Хамгийн өндөр үнэ = 98000 (ノートPC), хамгийн бага үнэ = 3200 (マウス)

## Дасгал 2: INSERT / UPDATE / DELETE

### ①

```sql
INSERT INTO users (name, email) VALUES ('中村健二', 'nakamura@example.com');
```

**Үр дүн (лавлагаа):** `id=4` болж «中村健二» нэмэгдэнэ.

### ②

```sql
INSERT INTO products (name, price) VALUES ('USBハブ', 2800);
```

**Үр дүн (лавлагаа):** `id=4` болж «USBハブ» нэмэгдэнэ.

### ③

```sql
-- Эхлээд id-г шалгана
SELECT id FROM users WHERE name = '田中太郎';     -- → 1
SELECT id FROM products WHERE name = 'USBハブ';   -- → 4

-- Шалгасан id-г ашиглан захиалга нэмэх
INSERT INTO orders (user_id, product_id, quantity) VALUES (1, 4, 3);
```

**Үр дүн (лавлагаа):** «田中太郎 3 ширхэг USBハブ захиалсан» өгөгдөл `id=6`-тай захиалга болж нэмэгдэнэ.

### ④

```sql
-- Урьдчилан шалгах
SELECT * FROM products WHERE name = 'ノートPC';

UPDATE products SET price = 95000 WHERE name = 'ノートPC';
```

**Үр дүн (лавлагаа):** ノートPC-ийн үнэ 98000 иен → 95000 иен болж өөрчлөгдөнө.

### ⑤

```sql
-- Гадаад түлхүүрийн хязгаарлалттай тул orders → users гэсэн дарааллаар устгана
DELETE FROM orders
WHERE user_id = (SELECT id FROM users WHERE name = '中村健二');

DELETE FROM users WHERE name = '中村健二';
```

**Үр дүн (лавлагаа):** 中村健二 энэ дасгалын явцад нэг ч захиалга нэмээгүй тул эхний `DELETE` **0 бичлэгт** нөлөөлнө (юу ч устгагдахгүй＝хэвийн үр дүн). 2 дахь `DELETE`-ээр 中村健二(id=4) устгагдана.
Эхлээд `users`-ийг устгахыг оролдвол гадаад түлхүүрийн хязгаарлалтаас болж алдаа гарна гэдэг нь гол санаа (энэ удаа 中村健二-ийн захиалга бодитоор байхгүй тул алдаа гарахгүй ч дарааллыг сахих зуршил чухал).

## Дасгал 3: JOIN ба нэгтгэн тооцоолол

### ①

```sql
SELECT
    users.name      AS ユーザー名,
    products.name   AS 商品名,
    orders.quantity AS 数量,
    products.price * orders.quantity AS 合計金額
FROM orders
INNER JOIN users    ON orders.user_id    = users.id
INNER JOIN products ON orders.product_id = products.id
ORDER BY orders.id;
```

**Үр дүн (лавлагаа):**

| ユーザー名 | 商品名 | 数量 | 合計金額 |
|---|---|---|---|
| 田中太郎 | ノートPC | 1 | 98000 |
| 田中太郎 | マウス | 2 | 6400 |
| 鈴木花子 | キーボード | 1 | 8500 |
| 山田次郎 | ノートPC | 1 | 98000 |
| 鈴木花子 | ノートPC | 1 | 98000 |

### ②

```sql
SELECT
    products.name   AS 商品名,
    orders.quantity AS 数量,
    products.price * orders.quantity AS 金額
FROM orders
INNER JOIN users    ON orders.user_id    = users.id
INNER JOIN products ON orders.product_id = products.id
WHERE users.name = '田中太郎';
```

**Үр дүн (лавлагаа):**

| 商品名 | 数量 | 金額 |
|---|---|---|
| ノートPC | 1 | 98000 |
| マウス | 2 | 6400 |

### ③

```sql
SELECT
    products.name AS 商品名,
    SUM(orders.quantity) AS 販売数量,
    SUM(products.price * orders.quantity) AS 売上合計
FROM orders
INNER JOIN products ON orders.product_id = products.id
GROUP BY products.id, products.name
ORDER BY 売上合計 DESC;
```

**Үр дүн (лавлагаа):**

| 商品名 | 販売数量 | 売上合計 |
|---|---|---|
| ノートPC | 3 | 294000 |
| キーボード | 1 | 8500 |
| マウス | 2 | 6400 |

### ④

```sql
SELECT users.name, users.email
FROM users
LEFT JOIN orders ON users.id = orders.user_id
WHERE orders.id IS NULL;
```

**Үр дүн (лавлагаа):** Анхны өгөгдөлд 田中太郎, 鈴木花子, 山田次郎 бүгд дор хаяж 1 удаа захиалга өгсөн тул **үр дүн 0 бичлэг**.
(Дасгал 2-т нэмсэн 中村健二-г энэ үед хараахан устгаагүй байсан бол захиалгагүй 中村健二-ийн нэг бичлэг үр дүнд гарна. «Захиалгагүй хэрэглэгч байхгүй тул 0 бичлэг гарах нь ч зөв үр дүн» гэдэг нь энэ бодлогын гол санаа.)

## Дасгал 4: Ахисан түвшний бодлого

### ①

```sql
SELECT
    users.name AS ユーザー名,
    AVG(products.price * orders.quantity) AS 平均購入金額
FROM orders
INNER JOIN users    ON orders.user_id    = users.id
INNER JOIN products ON orders.product_id = products.id
GROUP BY users.id, users.name
ORDER BY 平均購入金額 DESC
LIMIT 1;
```

**Үр дүн (лавлагаа):** 1 захиалгад ногдох дундаж худалдан авалтын дүн нь 田中太郎 = (98000+6400)/2 = 52200 иен, 鈴木花子 = (8500+98000)/2 = 53250 иен, 山田次郎 = 98000 иен (ганц захиалгатай). Тиймээс **山田次郎 (98000 иен)** хамгийн өндөр.

### ②

```sql
SELECT
    users.name AS ユーザー名,
    MAX(orders.ordered_at) AS 最新注文日時
FROM orders
INNER JOIN users ON orders.user_id = users.id
GROUP BY users.id, users.name;
```

**Үр дүн (лавлагаа):** Анхны өгөгдлийг 1 `INSERT` командаар нэг дор бүртгэсэн тул гурван хүний `ordered_at` утга бүгд командыг ажиллуулсан агшны ижил огноо, цаг байна. Өөр өөр өдөр захиалга нэмбэл хэрэглэгч бүрийн «хамгийн сүүлийн захиалгын огноо, цаг» өөр өөр байгааг харах боломжтой болно.

### ③

```sql
SELECT
    users.name  AS ユーザー名,
    users.email AS メール
FROM orders
INNER JOIN users    ON orders.user_id    = users.id
INNER JOIN products ON orders.product_id = products.id
GROUP BY users.id, users.name, users.email
HAVING SUM(products.price * orders.quantity) >= 100000;
```

**Үр дүн (лавлагаа):**

| ユーザー名 | メール |
|---|---|
| 田中太郎 | tanaka@example.com |
| 鈴木花子 | suzuki@example.com |

田中太郎-ийн нийт худалдан авалтын дүн 104400 иен, 鈴木花子-ийнх 106500 иен тул хоёулаа 100000 иен буюу түүнээс их байна. 山田次郎-ийнх 98000 иен тул хамаарахгүй.
