## ဒီနေ့ရဲ့ လေ့ကျင့်ခန်း အကြောင်းအရာ

သင်ချိန် 09 မှာ ဖန်တီးခဲ့တဲ့ `school_db` ထဲက users / products / orders Table တွေကို သုံးပြီး မေးခွန်းတွေကို ဖြေပါ။

---

## လေ့ကျင့်ခန်း 1: အခြေခံ SELECT

```sql
-- ① orders Table ရဲ့ ဒေတာအားလုံးကို ပြပါ
--    မျှော်လင့်ထားတဲ့ Output: 5 ခု (သင်ချိန် 09 မှာ ထည့်ခဲ့တဲ့ Order ဒေတာအားလုံး)

-- ② products Table ကနေ price က 5000 ယန်း နဲ့ အထက် ဖြစ်တဲ့ ကုန်ပစ္စည်းတွေကို ထုတ်ယူပါ
--    မျှော်လင့်ထားတဲ့ Output: ノートPC (လက်ပ်တော့၊ 98000), キーボード (ကီးဘုတ်၊ 8500) ဆိုပြီး 2 ခု (マウス (မောက်စ်) က မပါ)

-- ③ users Table ထဲက User တွေကို id ရဲ့ ကြီးစဉ်ငယ်လိုက် (Descending) ပြပါ
--    မျှော်လင့်ထားတဲ့ Output: 山田次郎(id=3) → 鈴木花子(id=2) → 田中太郎(id=1) အစဉ်အတိုင်း

-- ④ products Table ကနေ ဈေးအကြီးဆုံး ကုန်ပစ္စည်းနဲ့ ဈေးအသက်သာဆုံး ကုန်ပစ္စည်းရဲ့ ဈေးနှုန်းကို ပြပါ
--    မျှော်လင့်ထားတဲ့ Output: အမြင့်ဆုံး 98000 / အနိမ့်ဆုံး 3200
```

## လေ့ကျင့်ခန်း 2: INSERT / UPDATE / DELETE

```sql
-- ① အောက်ပါ User ကို ထည့်ပါ
--    အမည်: 中村健二, Email: nakamura@example.com
--    မျှော်လင့်ထားတဲ့ Output: id=4 အဖြစ် 中村健二 ကို ထည့်ပေးမယ်

-- ② products Table ထဲကို 「USBハブ」(USB hub၊ ဈေးနှုန်း: 2800 ယန်း) ကို ထည့်ပါ
--    မျှော်လင့်ထားတဲ့ Output: id=4 အဖြစ် USBハブ(2800 ယန်း) ကို ထည့်ပေးမယ်

-- ③ 田中太郎 က USBハブ ကို 3 ခု မှာယူခဲ့တဲ့ မှတ်တမ်းကို orders ထဲ ထည့်ပါ
--    အရိပ်အမြွက်: အရင်ဆုံး 田中太郎 ရဲ့ id နဲ့ USBハブ ရဲ့ id ကို SELECT နဲ့ စစ်ပါ
--    (2 ဆင့်နဲ့ လုပ်လည်း ရတယ်။ Statement 1 ခုတည်းနဲ့ ရေးချင်သူတွေ သင်ခန်းစာ အခန်း 8 「Subquery」ကို ကြည့်ပါ)
--    မျှော်လင့်ထားတဲ့ Output: id=6 ရဲ့ Order အဖြစ် (user_id=1, product_id=4, quantity=3) ကို ထည့်ပေးမယ်

-- ④ ノートPC ရဲ့ ဈေးနှုန်းကို 95000 ယန်း လို့ ပြင်ပါ
--    အရိပ်အမြွက်: SELECT နဲ့ စစ်ပြီးမှ UPDATE လုပ်ပါ
--    မျှော်လင့်ထားတဲ့ Output: ノートPC ရဲ့ price က 98000 → 95000 ပြောင်းသွားမယ်

-- ⑤ ထည့်ခဲ့တဲ့ 中村健二 ရဲ့ Order ဒေတာ ရှိရင် ဖျက်ပြီး၊ ပြီးရင် 中村健二 ရဲ့ User မှတ်တမ်းကိုယ်တိုင်ကို ဖျက်ပါ
--    အရိပ်အမြွက်: Foreign Key Constraint ရှိလို့ orders ကို အရင် ဖျက်ဖို့ လိုပါတယ်
--    အရိပ်အမြွက်: 中村健二 ရဲ့ id ကို မသိရင်တောင် သင်ခန်းစာ အခန်း 8 「Subquery」ရေးနည်းကို သုံးရင်
--    (SELECT id FROM users WHERE name = '中村健二') နဲ့ Statement 1 ခုတည်းထဲ စုရေးနိုင်တယ်
--    မျှော်လင့်ထားတဲ့ Output: 中村健二 ရဲ့ Order က 0 ခုဖြစ်လို့ ပထမ DELETE က သက်ရောက်တဲ့ Row 0 ခု၊
--    ဒုတိယ DELETE နဲ့ 中村健二(id=4) ကို ဖျက်ပေးမယ်
```

## လေ့ကျင့်ခန်း 3: JOIN နဲ့ အုပ်စုလိုက်တွက်ချက်ခြင်း

(လေ့ကျင့်ခန်း 2 ရဲ့ ပြောင်းလဲမှုတွေ မတိုင်ခင်၊ သင်ချိန် 09 ရဲ့ ကနဦးဒေတာကို အခြေခံပြီး စဉ်းစားပါ)

```sql
-- ① Order အားလုံးကို 「User အမည်・ကုန်ပစ္စည်းအမည်・အရေအတွက်・စုစုပေါင်း ငွေပမာဏ」ပုံစံနဲ့ ပြပါ
--    မျှော်လင့်ထားတဲ့ Output: 5 ကြောင်း (田中太郎×2, 鈴木花子×2, 山田次郎×1)

-- ② 田中太郎 ရဲ့ Order စာရင်းကို ကုန်ပစ္စည်းအမည်နဲ့ ငွေပမာဏ တွဲပြီး ပြပါ
--    မျှော်လင့်ထားတဲ့ Output: ノートPC(1 ခု, 98000 ယန်း), マウス(2 ခု, 6400 ယန်း) ဆိုပြီး 2 ကြောင်း

-- ③ ကုန်ပစ္စည်းအလိုက် စုစုပေါင်းရောင်းရငွေကို 「ကုန်ပစ္စည်းအမည်・ရောင်းရတဲ့ အရေအတွက်・စုစုပေါင်းရောင်းရငွေ」ပုံစံနဲ့
--    စုစုပေါင်းရောင်းရငွေ ကြီးစဉ်ငယ်လိုက် (Descending) ပြပါ
--    မျှော်လင့်ထားတဲ့ Output: ノートPC(3 ခု, 294000 ယန်း) → キーボード(1 ခု, 8500 ယန်း) → マウス(2 ခု, 6400 ယန်း)

-- ④ တစ်ခါမှ မမှာယူဖူးသေးတဲ့ User ကို ရှာပါ
--    အရိပ်အမြွက်: LEFT JOIN + WHERE orders.id IS NULL ကို သုံးပါ
--    (ဒီ Pattern ရဲ့ ရှင်းလင်းချက်အတွက် သင်ခန်းစာ 5-1 「Order မမှာရသေးတဲ့ User တွေကိုပဲ ရှာခြင်း」ကို ကြည့်ပါ)
--    မျှော်လင့်ထားတဲ့ Output: 0 ခု (ကနဦးဒေတာမှာ လူတိုင်း အနည်းဆုံး 1 ကြိမ် မှာယူပြီးသားဖြစ်လို့)
```

## လေ့ကျင့်ခန်း 4: အဆင့်မြင့် မေးခွန်း (မဖြစ်မနေ မဟုတ်・အချိန်ပိုရင် စမ်းကြည့်ပါ)

လေ့ကျင့်ခန်း 1〜3 ကို လုပ်နိုင်ရင် ဒီနေ့ရဲ့ ပန်းတိုင် ပြည့်မီပါပြီ။ လေ့ကျင့်ခန်း 4 မှာ `HAVING` လို အကြောင်းအရာအသစ်တွေ ပါလို့
အားလုံးကို အတင်း ဖြေစရာ မလိုပါဘူး။ (ဆက်ပြီး သင်ချိန် 09 ရဲ့ ကနဦးဒေတာကို အခြေခံပြီး စဉ်းစားပါ)

```sql
-- ① User တစ်ယောက်ချင်းရဲ့ ပျမ်းမျှ ဝယ်ယူငွေပမာဏ အမြင့်ဆုံးဖြစ်တဲ့ User ကို ရှာပါ
--    မျှော်လင့်ထားတဲ့ Output: 山田次郎 (ပျမ်းမျှ 98000 ယန်း။ 田中太郎 52200 ယန်း, 鈴木花子 53250 ယန်း)

-- ② User တစ်ယောက်ချင်းရဲ့ 「နောက်ဆုံး မှာယူခဲ့တဲ့ ရက်စွဲနဲ့ အချိန်」ကို ပြပါ
--    အရိပ်အမြွက်: GROUP BY + MAX(ordered_at)
--    မျှော်လင့်ထားတဲ့ Output: ကနဦးဒေတာကို INSERT တစ်ကြိမ်တည်းနဲ့ စုထည့်ခဲ့လို့ ၃ ယောက်လုံး ရက်စွဲနဲ့ အချိန် တူနေမယ်

-- ③ Order ငွေပမာဏ စုစုပေါင်း 100000 ယန်း နဲ့ အထက် ဖြစ်တဲ့ User ရဲ့ အမည်နဲ့ Email ကို ပြပါ
--    အရိပ်အမြွက်: GROUP BY + HAVING SUM(...) >= 100000
--    (WHERE နဲ့ HAVING ရဲ့ ကွာခြားချက်အတွက် သင်ခန်းစာ အခန်း 7 「HAVING」ကို ကြည့်ပါ)
--    မျှော်လင့်ထားတဲ့ Output: 田中太郎(104400 ယန်း), 鈴木花子(106500 ယန်း) ဆိုပြီး 2 ယောက် (山田次郎 98000 ယန်း က မပါ)
```
