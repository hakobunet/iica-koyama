# သင်ချိန် 10 လေ့ကျင့်ခန်း｜အဖြေနမူနာ

> 🇯🇵 မူရင်း (ဂျပန်ဘာသာဖြင့်): [20260728_解答.md](<../../../1年生_データ設計とアプリ開発/前期/20260728/20260728_解答.md>) <!-- original-ja-link -->

`school_db` ထဲက users / products / orders ရဲ့ ကနဦးဒေတာ (သင်ချိန် 09 သင်ခန်းစာကို ကြည့်ပါ) ကို အခြေခံထားတဲ့ အဖြေနမူနာပါ။ ပစ္စည်းအမည်တွေထဲက ノートPC ဆိုတာ လက်ပ်တော့၊ マウス ဆိုတာ မောက်စ်၊ キーボード ဆိုတာ ကီးဘုတ် ဖြစ်ပါတယ်။
လေ့ကျင့်ခန်း 1・လေ့ကျင့်ခန်း 3・လေ့ကျင့်ခန်း 4 ကို သီးသန့် ဖော်ပြထားခြင်း မရှိရင် 「လေ့ကျင့်ခန်း 2 ကို မ Run ခင်က ကနဦးဒေတာ」ကို အခြေခံပြီး စဉ်းစားပါ
(လေ့ကျင့်ခန်း 2 ကိုတော့ ①→⑤ အစဉ်အတိုင်း Run တဲ့ ဆက်တိုက် လုပ်ဆောင်ချက်အဖြစ် သတ်မှတ်ပါတယ်)။

```
users Table (ကနဦးဒေတာ)
id │ name     │ email
───┼──────────┼────────────────────
 1 │ 田中太郎 │ tanaka@example.com
 2 │ 鈴木花子 │ suzuki@example.com
 3 │ 山田次郎 │ yamada@example.com

products Table (ကနဦးဒေတာ)
id │ name       │ price
───┼────────────┼───────
 1 │ ノートPC   │ 98000
 2 │ マウス     │  3200
 3 │ キーボード │  8500

orders Table (ကနဦးဒေတာ)
id │ user_id │ product_id │ quantity
───┼─────────┼────────────┼─────────
 1 │    1    │     1      │    1     -- 田中太郎: ノートPC ×1
 2 │    1    │     2      │    2     -- 田中太郎: マウス ×2
 3 │    2    │     3      │    1     -- 鈴木花子: キーボード ×1
 4 │    3    │     1      │    1     -- 山田次郎: ノートPC ×1
 5 │    2    │     1      │    1     -- 鈴木花子: ノートPC ×1
```

## လေ့ကျင့်ခန်း 1: အခြေခံ SELECT

### ①

```sql
SELECT * FROM orders;
```

**ရလဒ် (ကိုးကားရန်):** အပေါ်က ကနဦးဒေတာ 5 ခုကို ဒီအတိုင်း ပြပေးပါတယ် (`ordered_at` မှာ INSERT လုပ်ခဲ့တဲ့ အချိန်ရဲ့ ရက်စွဲနဲ့ အချိန် ဝင်နေပါတယ်)။

### ②

```sql
SELECT * FROM products WHERE price >= 5000;
```

**ရလဒ် (ကိုးကားရန်):**

| name | price |
|------|-------|
| ノートPC | 98000 |
| キーボード | 8500 |

マウス (Mouse၊ 3200 ယန်း) က 5000 ယန်း အောက် ဖြစ်လို့ မပါပါ။

### ③

```sql
SELECT * FROM users ORDER BY id DESC;
```

**ရလဒ် (ကိုးကားရန်):** 山田次郎(id=3) → 鈴木花子(id=2) → 田中太郎(id=1) အစဉ်အတိုင်း ပြပေးပါတယ်။

### ④

```sql
SELECT MAX(price) AS 最高額, MIN(price) AS 最安値 FROM products;
```

**ရလဒ် (ကိုးကားရန်):** 最高額 (အမြင့်ဆုံး) = 98000 (ノートPC)、最安値 (အနိမ့်ဆုံး) = 3200 (マウス)

## လေ့ကျင့်ခန်း 2: INSERT / UPDATE / DELETE

### ①

```sql
INSERT INTO users (name, email) VALUES ('中村健二', 'nakamura@example.com');
```

**ရလဒ် (ကိုးကားရန်):** `id=4` အဖြစ် 「中村健二」ကို ထည့်ပေးပါတယ်။

### ②

```sql
INSERT INTO products (name, price) VALUES ('USBハブ', 2800);
```

**ရလဒ် (ကိုးကားရန်):** `id=4` အဖြစ် 「USBハブ」(USB Hub) ကို ထည့်ပေးပါတယ်။

### ③

```sql
-- အရင်ဆုံး id ကို စစ်ပါ
SELECT id FROM users WHERE name = '田中太郎';     -- → 1
SELECT id FROM products WHERE name = 'USBハブ';   -- → 4

-- စစ်ထားတဲ့ id ကို သုံးပြီး Order ကို ထည့်ခြင်း
INSERT INTO orders (user_id, product_id, quantity) VALUES (1, 4, 3);
```

**ရလဒ် (ကိုးကားရန်):** `id=6` ရဲ့ Order အဖြစ် 「田中太郎 က USBハブ ကို 3 ခု」Order မှာခဲ့တဲ့ ဒေတာကို ထည့်ပေးပါတယ်။

### ④

```sql
-- ကြိုတင်စစ်ဆေးခြင်း
SELECT * FROM products WHERE name = 'ノートPC';

UPDATE products SET price = 95000 WHERE name = 'ノートPC';
```

**ရလဒ် (ကိုးကားရန်):** ノートPC (Laptop) ရဲ့ ဈေးနှုန်းက 98000 ယန်း → 95000 ယန်း ပြောင်းသွားပါတယ်။

### ⑤

```sql
-- Foreign Key Constraint ရှိလို့ orders → users အစဉ်အတိုင်း ဖျက်ပါ
DELETE FROM orders
WHERE user_id = (SELECT id FROM users WHERE name = '中村健二');

DELETE FROM users WHERE name = '中村健二';
```

**ရလဒ် (ကိုးကားရန်):** 中村健二 က ဒီလေ့ကျင့်ခန်းထဲမှာ Order တစ်ခုမှ မထည့်ထားလို့ ပထမ `DELETE` က **သက်ရောက်တဲ့ Row 0 ခု** ပါ (ဘာမှ မဖျက်ပါ＝ ပုံမှန် ရလဒ်ပါ)။ ဒုတိယ `DELETE` နဲ့ 中村健二(id=4) ကို ဖျက်ပေးပါတယ်။
`users` ကို အရင်ဖျက်ဖို့ ကြိုးစားရင် Foreign Key Constraint ကြောင့် Error ဖြစ်မယ်ဆိုတာက အဓိကအချက်ပါ (ဒီတစ်ခါတော့ 中村健二 ရဲ့ Order တကယ် မရှိလို့ သက်ရောက်မှု မရှိပေမဲ့ အစဉ်လိုက်ဖျက်တဲ့ အလေ့အကျင့်က အရေးကြီးပါတယ်)။

## လေ့ကျင့်ခန်း 3: JOIN နဲ့ ဒေတာအုပ်စုလိုက် တွက်ချက်ခြင်း

### ①

```sql
SELECT
    users.name      AS ユーザー名,
    products.name   AS 商品名,
    orders.quantity AS 数量,
    products.price * orders.quantity AS 合計金額
FROM orders
INNER JOIN users    ON orders.user_id    = users.id
INNER JOIN products ON orders.product_id = products.id
ORDER BY orders.id;
```

**ရလဒ် (ကိုးကားရန်):** ユーザー名 က အသုံးပြုသူအမည်၊ 商品名 က ပစ္စည်းအမည်၊ 数量 က အရေအတွက်၊ 合計金額 က စုစုပေါင်းငွေပမာဏ ဖြစ်ပါတယ်။

| ユーザー名 | 商品名 | 数量 | 合計金額 |
|---|---|---|---|
| 田中太郎 | ノートPC | 1 | 98000 |
| 田中太郎 | マウス | 2 | 6400 |
| 鈴木花子 | キーボード | 1 | 8500 |
| 山田次郎 | ノートPC | 1 | 98000 |
| 鈴木花子 | ノートPC | 1 | 98000 |

### ②

```sql
SELECT
    products.name   AS 商品名,
    orders.quantity AS 数量,
    products.price * orders.quantity AS 金額
FROM orders
INNER JOIN users    ON orders.user_id    = users.id
INNER JOIN products ON orders.product_id = products.id
WHERE users.name = '田中太郎';
```

**ရလဒ် (ကိုးကားရန်):** 商品名 က ပစ္စည်းအမည်၊ 数量 က အရေအတွက်၊ 金額 က ငွေပမာဏ ဖြစ်ပါတယ်။

| 商品名 | 数量 | 金額 |
|---|---|---|
| ノートPC | 1 | 98000 |
| マウス | 2 | 6400 |

### ③

```sql
SELECT
    products.name AS 商品名,
    SUM(orders.quantity) AS 販売数量,
    SUM(products.price * orders.quantity) AS 売上合計
FROM orders
INNER JOIN products ON orders.product_id = products.id
GROUP BY products.id, products.name
ORDER BY 売上合計 DESC;
```

**ရလဒ် (ကိုးကားရန်):** 商品名 က ပစ္စည်းအမည်၊ 販売数量 က ရောင်းခဲ့တဲ့ အရေအတွက်၊ 売上合計 က စုစုပေါင်းရောင်းရငွေ ဖြစ်ပါတယ်။

| 商品名 | 販売数量 | 売上合計 |
|---|---|---|
| ノートPC | 3 | 294000 |
| キーボード | 1 | 8500 |
| マウス | 2 | 6400 |

### ④

```sql
SELECT users.name, users.email
FROM users
LEFT JOIN orders ON users.id = orders.user_id
WHERE orders.id IS NULL;
```

**ရလဒ် (ကိုးကားရန်):** ကနဦးဒေတာမှာ 田中太郎・鈴木花子・山田次郎 အားလုံး အနည်းဆုံး 1 ကြိမ် Order မှာပြီးသားဖြစ်လို့ **ရလဒ်က 0 ခု** ပါ။
(လေ့ကျင့်ခန်း 2 မှာ ထည့်ခဲ့တဲ့ 中村健二 ကို ဒီအချိန်မှာ မဖျက်ရသေးတဲ့ အခြေအနေဆိုရင် Order မရှိတဲ့ 中村健二 တစ်ယောက်တည်း ထွက်လာပါလိမ့်မယ်။ 「Order 0 ခုရှိတဲ့ User မရှိဘူး＝ 0 ခုဆိုတာလည်း မှန်ကန်တဲ့ ရလဒ်ပါပဲ」ဆိုတာက ဒီမေးခွန်းရဲ့ အဓိကအချက်ပါ။)

## လေ့ကျင့်ခန်း 4: အဆင့်မြင့် မေးခွန်း

### ①

```sql
SELECT
    users.name AS ユーザー名,
    AVG(products.price * orders.quantity) AS 平均購入金額
FROM orders
INNER JOIN users    ON orders.user_id    = users.id
INNER JOIN products ON orders.product_id = products.id
GROUP BY users.id, users.name
ORDER BY 平均購入金額 DESC
LIMIT 1;
```

**ရလဒ် (ကိုးကားရန်):** User တစ်ယောက်ချင်းရဲ့ Order တစ်ခုလျှင် ပျမ်းမျှ ဝယ်ယူငွေပမာဏက 田中太郎 = (98000+6400)/2 = 52200 ယန်း、鈴木花子 = (8500+98000)/2 = 53250 ယန်း、山田次郎 = 98000 ယန်း (Order 1 ခုတည်း)။ ဒါကြောင့် **山田次郎 (98000 ယန်း)** က အမြင့်ဆုံးပါ။

### ②

```sql
SELECT
    users.name AS ユーザー名,
    MAX(orders.ordered_at) AS 最新注文日時
FROM orders
INNER JOIN users ON orders.user_id = users.id
GROUP BY users.id, users.name;
```

**ရလဒ် (ကိုးကားရန်):** ကနဦးဒေတာကို `INSERT` Statement 1 ခုတည်းနဲ့ စုထည့်ခဲ့လို့ User ၃ ယောက်လုံးရဲ့ `ordered_at` က Statement ကို Run ခဲ့တဲ့ အချိန်ရဲ့ တူညီတဲ့ ရက်စွဲနဲ့ အချိန် ဖြစ်နေပါတယ်။ ရက်ခွဲပြီး Order ထည့်ကြည့်ရင် User တစ်ယောက်ချင်း မတူညီတဲ့ 「နောက်ဆုံး Order မှာတဲ့ ရက်စွဲနဲ့ အချိန်」ကို မြင်ရပါလိမ့်မယ်။

### ③

```sql
SELECT
    users.name  AS ユーザー名,
    users.email AS メール
FROM orders
INNER JOIN users    ON orders.user_id    = users.id
INNER JOIN products ON orders.product_id = products.id
GROUP BY users.id, users.name, users.email
HAVING SUM(products.price * orders.quantity) >= 100000;
```

**ရလဒ် (ကိုးကားရန်):** ユーザー名 က အသုံးပြုသူအမည်၊ メール က အီးမေးလ်လိပ်စာ ဖြစ်ပါတယ်။

| ユーザー名 | メール |
|---|---|
| 田中太郎 | tanaka@example.com |
| 鈴木花子 | suzuki@example.com |

田中太郎 ရဲ့ စုစုပေါင်း ဝယ်ယူငွေပမာဏက 104400 ယန်း、鈴木花子 က 106500 ယန်း ဖြစ်လို့ ၂ ယောက်လုံး 100000 ယန်း နဲ့ အထက်ပါ။ 山田次郎 က 98000 ယန်း ဖြစ်လို့ မပါပါ။
