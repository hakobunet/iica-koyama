# समग्र प्रोजेक्ट — निर्माण नियम (न्यूनतम मापदण्ड)

> 🇯🇵 मूल प्रति (जापानी भाषामा): [課題提出ルール.md](<../../1年生_前期_ITシステム基礎/課題提出ルール/課題提出ルール.md>) <!-- original-ja-link -->

## सारांश
 
तलका नियमहरू **सबै पूरा गरेको काम** मात्र बुझाउनुहोस्।

कुन प्रविधि (GAS/localStorage आदि) प्रयोग गर्ने भन्ने कुराले फरक पार्दैन।  
**"के-के गर्न सकिन्छ" भन्ने आधारमा मूल्याङ्कन गरिन्छ।**

---

## अनिवार्य कार्यात्मक आवश्यकताहरू

### 1. CRUD सञ्चालन (४ वटै अनिवार्य)

HTML को स्क्रिनमा तलका सबै काम गर्न सकिनुपर्छ।

| काम | विवरण | उदाहरण |
|------|------|----|
| **दर्ता (Create)** | नयाँ डेटा थप्न सकिनु | फारम भरेर सेभ बटन थिच्ने |
| **हेर्ने (Read)** | दर्ता गरिएको डेटा सूची र विस्तृत रूपमा हेर्न सकिनु | तालिका वा कार्डमा सूची देखाउने |
| **अपडेट (Update)** | पहिले नै भएको डेटा सम्पादन गरेर पुरानो डेटाको ठाउँमा सुरक्षित गर्न सकिनु | सम्पादन बटन थिचेर विवरण बदल्ने |
| **मेटाउने (Delete)** | नचाहिने डेटा मेटाउन सकिनु | मेटाउने बटन थिचेर डेटा मेटाउने |

### 2. बाहिरी API सँगको सञ्चार

बाहिरी API मा रिक्वेस्ट पठाएर, प्राप्त डेटा स्क्रिनमा देखाउनुपर्छ।

- उदाहरण: मौसम API/विनिमय दर API/समाचार API आदि
- API को रेस्पोन्स जस्ताको तस्तै देखाउने मात्र होइन, **स्क्रिनमा देखाइने सामग्री वा सिस्टमको काममा प्रयोग** गर्नुपर्छ

---

## अनिवार्य कोड आवश्यकताहरू

जुनसुकै प्रविधि भए पनि, कोडभित्र तलका कुराहरू समावेश गर्नुहोस्।

- [ ] **आफैँले बनाएको function** २ वा सोभन्दा बढी परिभाषित गर्ने
- [ ] **सर्तअनुसार शाखा विभाजन** (`if / else`) कम्तीमा १ वटा लेख्ने
- [ ] **loop** (`for` वा `while`) १ वा सोभन्दा बढी लेख्ने

---

## निषेधित कुराहरू

| NG | कारण |
|----|------|
| नमुना कोड जस्ताको तस्तै कपी गरेर बुझाउने | आफैँले लेखेको मानिँदैन |
| प्रयोगकर्ताले जे गरे पनि सधैँ एउटै स्क्रिन मात्र देखाउने | सिस्टमको रूपमा काम गरिरहेको हुँदैन |
| CRUD को केही भाग (विशेष गरी अपडेट/मेटाउने) implement नगरिएको | न्यूनतम आवश्यकता पूरा हुँदैन |
| API कल गर्ने मात्र, नतिजा कतै पनि प्रयोग नगर्ने | सञ्चारको कुनै अर्थ रहँदैन |

---

## प्रस्तुतिमा व्याख्या गर्नुपर्ने कुराहरू

कक्षा २० को प्रस्तुति (करिब ५ मिनेट) मा तलका कुराहरू **आफ्नै शब्दमा** व्याख्या गर्न सक्नुपर्छ।

1. **केका लागि बनाइयो** (उद्देश्य/समाधान गर्ने समस्या)
2. **कसरी प्रयोग गर्ने** (वास्तवमै demo गरेर CRUD का चारै काम गरेर देखाउने)
3. **बाहिरी API कसरी उपयोग गरियो**
4. **कोडमा आफूले सोचेर विशेष तरिकाले बनाएको कम्तीमा १ वटा भाग**, कोड स्क्रिनमा देखाउँदै व्याख्या गर्ने

## मूल्याङ्कन मापदण्ड (पूर्णाङ्क १००)

| विषय | अङ्क | मापदण्ड |
|------|------|------|
| CRUD को इम्प्लिमेन्टेसन | ४० अङ्क | चारवटै कामको प्रत्येकलाई १० अङ्क। काम गरेमा पूरा अङ्क |
| बाहिरी API को उपयोग | २० अङ्क | API कल मात्र गरेमा १० अङ्क, नतिजा सिस्टममा प्रयोग गरेमा थप १० अङ्क |
| मौलिकता/पूर्णता | २० अङ्क | आफैँले सोचेको विषय हो कि होइन/error बिना चल्छ कि चल्दैन |
| प्रस्तुति/व्याख्या क्षमता | २० अङ्क | कोडले कसरी काम गर्छ भनेर आफ्नै शब्दमा व्याख्या गर्न सक्छ कि सक्दैन |

## सन्दर्भ: "पास हुने स्तर" का उदाहरण

### ✅ न्यूनतम स्तर पूरा गरेका उदाहरण

- **टास्क व्यवस्थापन टुल**: टास्क थप्न, सूची देखाउन, सम्पन्न भएको रूपमा अपडेट गर्न र मेटाउन सकिन्छ, साथै API बाट आजको मौसम देखाइन्छ
- **पुस्तक व्यवस्थापन**: किताब दर्ता गर्न, सूची हेर्न, सम्पादन गर्न र मेटाउन सकिन्छ, साथै ISBN बाट API मार्फत किताबको जानकारी ल्याएर स्वतः भरिन्छ
- **मेमो एप**: मेमो बनाउन, सूची हेर्न, सम्पादन गर्न र मेटाउन सकिन्छ, साथै मौसम API प्रयोग गरेर आजको मुड रेकर्ड गर्ने ठाउँमा देखाइन्छ

### ❌ नियम पूरा नगरेका उदाहरण

- दर्ता र हेर्ने मात्र छ, अपडेट/मेटाउने छैन
- API कल गरिएको छ, तर नतिजा कतै पनि देखाइएको वा प्रयोग गरिएको छैन
- फारम छ, तर डेटा सेभ हुँदैन (पेज रिफ्रेस गर्दा हराउँछ)

## बारम्बार सोधिने प्रश्नहरू

**Q. GAS प्रयोग गर्नैपर्छ?**  
A. अनिवार्य होइन। CRUD र API का आवश्यकता पूरा हुन्छ भने जुनसुकै प्रविधि प्रयोग गर्न सकिन्छ।

**Q. डेटा जहाँ सेभ गरे पनि हुन्छ?**  
A. GAS＋स्प्रेडसिट वा localStorage जस्ता, पेज फेरि लोड गर्दा पनि डेटा सुरक्षित रहने तरिका रोज्नुहोस्।


**Q. टिम बनाएर बनाउन मिल्छ?**  
A. सामान्यतया एक्लै बनाउनुपर्छ। प्रस्तुतिमा कोड आफैँले व्याख्या गर्न सक्नु शर्त हो।
