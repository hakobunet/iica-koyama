## အကျဉ်းချုပ်
 
အောက်ပါ စည်းမျဉ်းတွေကို **အားလုံး ပြည့်မီတဲ့ project** ကို တင်သွင်းပါ။

သုံးမယ့် နည်းပညာ（GAS・localStorage စသည်）က ဘာဖြစ်ဖြစ် ရပါတယ်။  
**「ဘာတွေ လုပ်နိုင်လဲ」ဆိုတာနဲ့ အမှတ်ပေးပါမယ်။**

---

## မဖြစ်မနေ ပါဝင်ရမယ့် လုပ်ဆောင်ချက်များ

### 1. CRUD လုပ်ဆောင်ချက်（4 ခုလုံး မဖြစ်မနေ လိုအပ်）

HTML screen ပေါ်မှာ အောက်ပါ လုပ်ဆောင်ချက်အားလုံးကို လုပ်နိုင်ရပါမယ်။

| လုပ်ဆောင်ချက် | အကြောင်းအရာ | ဥပမာ |
|------|------|----|
| **မှတ်ပုံတင်ခြင်း（Create）** | Data အသစ်ကို ထည့်နိုင်တယ် | Form မှာ ဖြည့်ပြီး save ခလုတ်ကို နှိပ်တယ် |
| **ကြည့်ရှုခြင်း（Read）** | မှတ်ပုံတင်ထားတဲ့ data ကို စာရင်း・အသေးစိတ် အဖြစ် ကြည့်နိုင်တယ် | Table သို့မဟုတ် card နဲ့ စာရင်းပြတယ် |
| **ပြင်ဆင်ခြင်း（Update）** | ရှိပြီးသား data ကို ပြင်ပြီး overwrite လုပ်နိုင်တယ် | Edit ခလုတ်ကို နှိပ်ပြီး အကြောင်းအရာကို ပြောင်းတယ် |
| **ဖျက်ခြင်း（Delete）** | မလိုတော့တဲ့ data ကို ဖျက်နိုင်တယ် | Delete ခလုတ်ကို နှိပ်ပြီး data ကို ဖျက်တယ် |

### 2. ပြင်ပ API နဲ့ ဆက်သွယ်ခြင်း

ပြင်ပ API ကို request ပို့ပြီး ရလာတဲ့ data ကို screen မှာ ပြသရပါမယ်။

- ဥပမာ：ရာသီဥတု API・ငွေလဲနှုန်း API・သတင်း API စသည်
- API ရဲ့ response ကို ဒီအတိုင်း ပြရုံသာမက **screen ပြသပုံ ဒါမှမဟုတ် system ရဲ့ လုပ်ဆောင်ပုံမှာ အသုံးချ** ရပါမယ်

---

## Code မှာ မဖြစ်မနေ ပါဝင်ရမယ့် အချက်များ

ဘယ်နည်းပညာ သုံးသုံး code ထဲမှာ အောက်ပါတို့ ပါဝင်ရပါမယ်။

- [ ] **ကိုယ်တိုင်ရေးတဲ့ function** ကို 2 ခု သို့မဟုတ် ထို့ထက်ပို၍ သတ်မှတ်ရမယ်
- [ ] **Conditional branch**（`if / else`）ကို အနည်းဆုံး 1 ခု ရေးရမယ်
- [ ] **Loop**（`for` သို့မဟုတ် `while`）ကို အနည်းဆုံး 1 ခု ရေးရမယ်

---

## တားမြစ်ချက်များ

| NG | အကြောင်းရင်း |
|----|------|
| နမူနာ code ကို ဒီအတိုင်း copy ကူးပြီး တင်သွင်းခြင်း | ကိုယ်တိုင် ရေးထားတာ မဟုတ်လို့ |
| User ရဲ့ လုပ်ဆောင်မှုနဲ့ မသက်ဆိုင်ဘဲ အမြဲတမ်း screen တစ်ခုတည်းကိုပဲ ပြနေခြင်း | System အဖြစ် အလုပ်မလုပ်လို့ |
| CRUD ရဲ့ တစ်စိတ်တစ်ပိုင်း（အထူးသဖြင့် ပြင်ဆင်ခြင်း・ဖျက်ခြင်း）ကို မရေးရသေးခြင်း | အနိမ့်ဆုံး လိုအပ်ချက်ကို မပြည့်မီလို့ |
| API ကို ခေါ်ရုံသာ ခေါ်ပြီး ရလဒ်ကို ဘာမှ အသုံးမချခြင်း | ဆက်သွယ်ရကျိုး မရှိလို့ |

## တင်ပြချက်မှာ ရှင်းပြရမယ့် လိုအပ်ချက်

သင်ခန်းစာ 20 မှာ လုပ်မယ့် တင်ပြချက်（5 မိနစ်ခန့်）မှာ အောက်ပါတို့ကို **ကိုယ့်စကားနဲ့ကိုယ်** ရှင်းပြနိုင်ရပါမယ်။

1. **ဘာအတွက် ဖန်တီးခဲ့တာလဲ**（ရည်ရွယ်ချက်・ဖြေရှင်းပေးမယ့် ပြဿနာ）
2. **ဘယ်လို သုံးရမလဲ**（တကယ် demo ပြပြီး CRUD အားလုံးကို လုပ်ပြရမယ်）
3. **ပြင်ပ API ကို ဘယ်လို အသုံးချခဲ့လဲ**
4. **Code ရေးရာမှာ ကိုယ်တိုင် စဉ်းစားဖန်တီးထားတဲ့ အပိုင်း အနည်းဆုံး 1 ခု** ကို code ကို screen မှာ ပြရင်း ရှင်းပြရမယ်

## ကိုးကားရန်：「အောင်မှတ်မီတဲ့ အဆင့်」ရဲ့ ဥပမာများ

### ✅ အနိမ့်ဆုံး လိုအပ်ချက်တွေကို ပြည့်မီတဲ့ ဥပမာ

- **Task စီမံခန့်ခွဲမှု tool**：task ကို ထည့်ခြင်း・စာရင်းပြခြင်း・ပြီးစီးကြောင်း အခြေအနေပြောင်းခြင်း・ဖျက်ခြင်း လုပ်နိုင်ပြီး ဒီနေ့ ရာသီဥတုကို API နဲ့ ပြသတယ်
- **စာအုပ်စာရင်း စီမံခန့်ခွဲမှု**：စာအုပ်ကို မှတ်ပုံတင်・စာရင်းပြ・ပြင်ဆင်・ဖျက် လုပ်နိုင်ပြီး ISBN ကနေ စာအုပ်အချက်အလက်ကို API နဲ့ ရယူပြီး အလိုအလျောက် ဖြည့်ပေးတယ်
- **Memo app**：memo ကို ဖန်တီး・စာရင်းပြ・ပြင်ဆင်・ဖျက် လုပ်နိုင်ပြီး ရာသီဥတု API နဲ့ ဒီနေ့ စိတ်ခံစားမှုကို မှတ်တမ်းကွက်မှာ ပြသတယ်

### ❌ စည်းမျဉ်းကို မပြည့်မီတဲ့ ဥပမာ

- မှတ်ပုံတင်ခြင်းနဲ့ ကြည့်ရှုခြင်းပဲ ရှိပြီး ပြင်ဆင်ခြင်း・ဖျက်ခြင်း မရှိဘူး
- API ကို ခေါ်ထားပေမယ့် ရလဒ်ကို ဘယ်နေရာမှာမှ မပြ၊ အသုံးမချဘူး
- Form ရှိပေမယ့် data ကို မသိမ်းဘူး（page ကို refresh လုပ်ရင် ပျောက်သွားတယ်）

## မေးလေ့ရှိတဲ့ မေးခွန်းများ

**Q. GAS ကို မဖြစ်မနေ သုံးရမလား？**  
A. မဖြစ်မနေ မဟုတ်ပါဘူး။ CRUD နဲ့ API လိုအပ်ချက်တွေကို ပြည့်မီရင် ဘယ်နည်းပညာ သုံးသုံး ရပါတယ်။

**Q. Data သိမ်းမယ့်နေရာက ဘယ်မှာဖြစ်ဖြစ် ရလား？**  
A. GAS＋spreadsheet・localStorage စသဖြင့် page ကို reload လုပ်ရင်တောင် data ကျန်နေမယ့် နည်းလမ်းကို ရွေးပါ။

**Q. Team နဲ့ ဖန်တီးလို့ ရလား？**  
A. အခြေခံအားဖြင့် တစ်ယောက်တည်း ဖန်တီးရပါမယ်။ တင်ပြချက်မှာ code ကို ကိုယ်တိုင် ရှင်းပြနိုင်ဖို့ လိုအပ်ပါတယ်။
