# Final Project — Project Rules (Minimum Requirements)

> 🇯🇵 Original (Japanese version): [課題提出ルール.md](<../../1年生_前期_ITシステム基礎/課題提出ルール/課題提出ルール.md>) <!-- original-ja-link -->

## Overview
 
Submit a **project that meets all** of the rules below.

You can use any technology you like (GAS, localStorage, etc.).  
**We grade you on "what your app can do."**

---

## Required Features

### 1. CRUD Operations (all 4 are required)

Users must be able to perform all of the following operations through the HTML interface.

| Operation | What it means | Example |
|------|------|----|
| **Create** | You can add new data | Fill in a form and click the Save button |
| **Read** | You can view the saved data as a list or in detail | Show a list in a table or as cards |
| **Update** | You can edit existing data and overwrite it | Click the Edit button and change the contents |
| **Delete** | You can remove data you no longer need | Click the Delete button to remove the data |

### 2. Communicating with an External API

Send a request to an external API and show the data you get on the screen.

- Examples: a weather API, an exchange rate API, a news API, etc.
- Don't just display the API response unchanged; **use the data to affect what the interface displays or how the system works**

---

## Required Code Elements

Whatever technology you use, your code must include the following.

- [ ] Define at least 2 **functions of your own**
- [ ] Write at least 1 **conditional** (`if / else`)
- [ ] Write at least 1 **loop** (`for` or `while`)

---

## Not Allowed

| Not allowed | Reason |
|----|------|
| Copying sample code as is and submitting it | It doesn't count as writing it yourself |
| Only showing the same screen all the time, regardless of what the user does | It doesn't work as a system |
| Leaving any CRUD operation unimplemented, especially Update or Delete | It doesn't meet the minimum requirements |
| Only calling an API without using the result for anything | There's no point in communicating with the API |

---

## What to Explain in Your Presentation

In the presentation in Class 20 (about 5 minutes), you must be able to explain the following **in your own words**.

1. **Why you made it** (its purpose and the problem it solves)
2. **How to use it** (do a live demo and show all the CRUD operations)
3. **How you used the external API**
4. **At least one part of the code that you put extra thought into**, while showing the code on screen

---

## Grading Criteria (out of 100 points)

| Item | Points | Criteria |
|------|------|------|
| CRUD implementation | 40 points | 10 points for each of the 4 operations. Full marks if they work |
| Use of the external API | 20 points | 10 points for just calling it, +10 points if the result is used in the system |
| Originality and completeness | 20 points | Did you come up with the project idea yourself? Does it run without errors? |
| Presentation and explanation | 20 points | Can you explain how the code works in your own words? |

## Reference: Examples of What Passes

### ✅ Examples that meet the minimum requirements

- **Task manager**: You can add tasks, show them in a list, mark them as done, and delete them, and it shows today's weather using an API
- **Book collection manager**: You can add, list, edit, and delete books, and it gets book information from the ISBN using an API to fill in the fields automatically
- **Memo app**: You can create, list, edit, and delete memos, and it uses a weather API to display today's mood in the record field

### ❌ Examples that don't meet the rules

- It only has Create and Read, with no Update or Delete
- It calls an API, but doesn't show or use the result anywhere
- There is a form, but the data isn't saved (it disappears when you reload the page)

## FAQ

**Q. Do I have to use GAS?**  
A. No, it's not required. You can use any technology as long as it meets the CRUD and API requirements.

**Q. Can I save the data anywhere?**  
A. Choose a method where the data stays even after you reload the page, such as GAS + a spreadsheet or localStorage.

**Q. Can I work in a team?**  
A. As a rule, each person makes their own project. You must be able to explain your code yourself in the presentation.
