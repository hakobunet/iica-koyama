# コマ26｜APIのURLを環境変数（.env）に切り出す - 実装手順

## 今日のゴール

- `school-frontend` の各ページに直書きされていた `http://localhost:8000` / `http://127.0.0.1:8000` を1箇所にまとめる
- `.env` ファイルを作り、APIのURLを環境変数 `NEXT_PUBLIC_API_URL` として管理する
- `.env.example`（値の入っていないテンプレート）をgitで共有し、`.env`（実際の値）はgit管理から外す
- fetchを使っている箇所をすべて `process.env.NEXT_PUBLIC_API_URL` 経由に書き換える

> **位置づけ：** これまでは `fetch("http://127.0.0.1:8000/api/students")` のように、APIのURLをファイルごとに直接書いていました。この書き方だと、開発環境と本番環境でURLが違うときにファイルを何箇所も書き換える必要があり、書き忘れによるバグの原因にもなります。今回は「変わる可能性がある値（URLやAPIキーなど）はコードに埋め込まず、環境変数として外に出す」という考え方を学びます。

---

## 全体像：何を作るか

```
.env（実際の値・gitには含めない）
  NEXT_PUBLIC_API_URL=http://127.0.0.1:8000
     │
     │ Next.jsが起動時に読み込む
     ▼
process.env.NEXT_PUBLIC_API_URL
     │
     ├─ app/login/page.tsx        （ログインAPI）
     ├─ app/register/page.tsx     （登録API）
     ├─ app/students/page.tsx     （一覧・追加・削除・ログアウトAPI）
     ├─ app/students/[id]/page.tsx（詳細・ログアウトAPI）
     └─ components/students/StudentDetail.tsx（更新API）
```

> 💡 **たとえるなら…住所を1箇所にまとめた連絡帳**
>
> これまでは、友達に手紙を送るたびに「田中さんの家は◯◯町3-1」と毎回自分で住所を書いていたようなものです。もし田中さんが引っ越したら、書いた手紙を全部書き直さなければいけません。`.env` は「連絡帳」のようなもので、住所（APIのURL）を1箇所にだけ書いておき、手紙（各ファイルのfetch）からは「連絡帳の田中さんの住所」を参照するようにします。引っ越し（URLの変更）があっても、連絡帳を1回書き換えるだけで済みます。

### なぜ `.env` と `.env.example` を分けるのか

`.env` にはこのアプリでは秘密の値は入っていませんが、一般的には接続先のDBパスワードやAPIキーなど、他人に見られたくない値が入ります。そのため `.env` 自体は `.gitignore` で除外し、gitでは共有しません。一方で「どんな変数名が必要か」はチームで共有したいので、値を空（またはダミー値）にした `.env.example` だけをコミットします。新しくプロジェクトに参加した人は `.env.example` をコピーして `.env` を作り、自分の環境に合わせて値を入れます。

### ファイル構成（今回さわるもの）

| 記号 | 意味 |
|---|---|
| 🆕 新規 | ファイルを新しく作る |
| ➕ 追加 | 既存ファイルにコードを追記する |
| 🔁 置き換え | 既存の処理を書き換える |

```
school-frontend/
├── .env                                       🆕 新規（実際の値・gitには含めない）
├── .env.example                               🆕 新規（テンプレート・gitに含める）
├── .gitignore                                 ➕ .env.example だけ除外を解除
├── app/login/page.tsx                         🔁 fetchのURLを環境変数に置き換え
├── app/register/page.tsx                      🔁 fetchのURLを環境変数に置き換え
├── app/students/page.tsx                      🔁 fetchのURLを環境変数に置き換え（4箇所）
├── app/students/[id]/page.tsx                 🔁 fetchのURLを環境変数に置き換え（2箇所）
└── components/students/StudentDetail.tsx      🔁 fetchのURLを環境変数に置き換え
```

## Step 1｜`.env` を作成する

**🆕 新規ファイル** — `school-frontend` 直下に `.env` を作ります。

```bash
# ▼ school-frontend/.env
NEXT_PUBLIC_API_URL=http://127.0.0.1:8000
```

- キー名の先頭に `NEXT_PUBLIC_` を付けるのがポイントです。Next.jsは `NEXT_PUBLIC_` が付いた環境変数だけを、ブラウザ側（クライアントコンポーネント）でも読めるようにビルドに埋め込みます。今回書き換える `fetch` はすべて `"use client"` の付いたコンポーネントの中にあるため、このプレフィックスが必須です。
- `NEXT_PUBLIC_` の付いていない環境変数（例：DBのパスワードなど）は、サーバー側のコードからしか読めません。ブラウザに見られたくない値には付けないようにします。

---

## Step 2｜`.env.example` を作成する

**🆕 新規ファイル** — チームで共有するテンプレートとして、同じ内容のファイルを作ります。今回は秘密情報を含まないURLなので、そのまま同じ値を書いておきます。

```bash
# ▼ school-frontend/.env.example
NEXT_PUBLIC_API_URL=http://127.0.0.1:8000
```

> ⚠️ パスワードやAPIキーのように本当に秘密の値を扱う場合は、`.env.example` には実際の値を書かず、`DB_PASSWORD=` のように空にしたり `your-api-key-here` のようなダミー値にしたりします。

---

## Step 3｜`.gitignore` で `.env.example` だけ除外を解除する

`create-next-app` が最初から用意している `.gitignore` には、次のように `.env*` というワイルドカードのルールがあります。

```
# env files (can opt-in for committing if needed)
.env*
```

このルールは `.env` だけでなく `.env.example` も含めて「`.env` から始まるファイル全部」を除外してしまいます。秘密情報を誤ってコミットしないための安全策としては正しい設定ですが、これだと共有したいはずの `.env.example` までgit管理から外れてしまいます。そこで、`.env.example` だけを例外的に除外しない設定を1行追加します。

**➕ 追加**

```
# env files (can opt-in for committing if needed)
.env*
!.env.example
```

`!` を先頭に付けると「このパターンは除外しない（＝gitで管理する）」という意味になります。`.env*` で一旦全部除外したあとに `!.env.example` で `.env.example` だけを復活させる、という順番が重要です（逆の順番だと効きません）。

---

## Step 4｜fetchのURLを環境変数に置き換える

ここまでで `.env` の準備はできましたが、実際のコードはまだ `http://127.0.0.1:8000` を直接見ています。各ファイルのfetch呼び出しを `process.env.NEXT_PUBLIC_API_URL` を使ったテンプレートリテラルに書き換えます。

### 4-1. `app/login/page.tsx`

**🔁 置き換え**

```tsx
// Before
const res = await fetch("http://127.0.0.1:8000/api/login", {

// After
const res = await fetch(`${process.env.NEXT_PUBLIC_API_URL}/api/login`, {
```

### 4-2. `app/register/page.tsx`

**🔁 置き換え**

```tsx
// Before
const res = await fetch("http://127.0.0.1:8000/api/register", {

// After
const res = await fetch(`${process.env.NEXT_PUBLIC_API_URL}/api/register`, {
```

### 4-3. `app/students/page.tsx`（4箇所）

**🔁 置き換え** — 一覧取得・生徒追加・生徒削除・ログアウトの4つのfetchを、それぞれ書き換えます。

```tsx
// 一覧取得（Before → After）
const res = await fetch("http://127.0.0.1:8000/api/students", {
const res = await fetch(`${process.env.NEXT_PUBLIC_API_URL}/api/students`, {

// 生徒追加（Before → After）
const res = await fetch("http://127.0.0.1:8000/api/students", {
const res = await fetch(`${process.env.NEXT_PUBLIC_API_URL}/api/students`, {

// 生徒削除（Before → After）
const res = await fetch(`http://127.0.0.1:8000/api/students/${id}`, {
const res = await fetch(`${process.env.NEXT_PUBLIC_API_URL}/api/students/${id}`, {

// ログアウト（Before → After）
await fetch("http://127.0.0.1:8000/api/logout", {
await fetch(`${process.env.NEXT_PUBLIC_API_URL}/api/logout`, {
```

### 4-4. `app/students/[id]/page.tsx`（2箇所）

**🔁 置き換え** — このファイルはもともと `http://localhost:8000`（`127.0.0.1` ではなく `localhost` 表記）で書かれていました。表記が揺れていること自体が「URLを1箇所にまとめる」ことの必要性を示しています。

```tsx
// 詳細取得（Before → After）
const res = await fetch(`http://localhost:8000/api/students/${params.id}`, {
const res = await fetch(`${process.env.NEXT_PUBLIC_API_URL}/api/students/${params.id}`, {

// ログアウト（Before → After）
await fetch("http://localhost:8000/api/logout", {
await fetch(`${process.env.NEXT_PUBLIC_API_URL}/api/logout`, {
```

### 4-5. `components/students/StudentDetail.tsx`

**🔁 置き換え**

```tsx
// Before
const res = await fetch(`http://localhost:8000/api/students/${student.id}`, {

// After
const res = await fetch(`${process.env.NEXT_PUBLIC_API_URL}/api/students/${student.id}`, {
```

> 💡 元の文字列が `"http://..."` の二重引用符（普通の文字列）だった箇所も、`${...}` を埋め込むためにバッククォート（\` \`）のテンプレートリテラルに変える必要があります。すでにテンプレートリテラルだった箇所（`` `http://127.0.0.1:8000/api/students/${id}` `` など）はそのままバッククォートを使い、中の文字列部分だけ差し替えます。

## 動作確認

```bash
# バックエンド
cd Laravel && php artisan serve   # http://localhost:8000

# フロントエンド
cd school-frontend && npm run dev # http://localhost:3000
```

> ⚠️ `.env` を新しく作ったり値を変更したりしたときは、`npm run dev` を一度止めて再起動してください。Next.jsは環境変数をビルド・起動のタイミングで読み込むため、サーバーを立ち上げたまま `.env` を書き換えても、ホットリロードでは反映されません。

| 確認項目 | 操作 | 期待する結果 |
|---|---|---|
| コード内に直書きURLが残っていないか | `grep -rn "localhost:8000\|127.0.0.1:8000" app components` を実行 | 何も出力されない（全部 `process.env` 経由に置き換わっている） |
| ログイン | `/login` からログインする | これまで通りログインでき、`/students` に遷移する |
| 一覧・詳細・追加・削除 | `/students` で一連の操作を行う | すべて今まで通り動作する（URLの見た目が変わっただけで挙動は変わらない） |
| 環境変数の切り替え | `.env` の値を一時的に別のポート（例：存在しないポート）に変えて再起動 | APIへの接続が失敗する＝ `.env` の値がちゃんと使われていることが確認できる（確認後は元の値に戻す） |
| gitでの見え方 | `git status` を実行 | `.env` は表示されない（除外されている）、`.env.example` は未追跡ファイルとして表示される |

## まとめ

| 概念 | 今回の対応箇所 |
|---|---|
| 環境変数への切り出し | `.env` の `NEXT_PUBLIC_API_URL` |
| クライアント側で環境変数を読む条件 | `NEXT_PUBLIC_` プレフィックス |
| 秘密情報をgitに含めない工夫 | `.gitignore` の `.env*` |
| テンプレートだけをチームで共有する工夫 | `.env.example` ＋ `!.env.example` による除外解除 |
| 環境変数の反映タイミング | `.env` 変更後は開発サーバーの再起動が必要 |
