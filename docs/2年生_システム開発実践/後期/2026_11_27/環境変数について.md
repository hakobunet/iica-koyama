# 環境変数について

自由制作の資料では、何度も「**APIキーやパスワードは GitHub にのせない**」「`.env` に書く」と書いてきました。
この `.env` に書いているものが **環境変数（かんきょうへんすう）** です。
ここでは、環境変数とは何か、なぜ使うのかを見ていきます。

[自由制作に戻る](../2026_10_09/2026_10_09_資料1.md)

---

## 1. 環境変数とは

**環境変数** は、プログラムの **外側** に置いておく設定の値です。
プログラムは、動くときにその値を **読みこんで** 使います。

```mermaid
graph LR
    A[.env ファイル<br>Vercel の設定画面] -->|動くときに読みこむ| B[プログラム]
```

| 環境変数に入れるもの | 例 |
|------------------|-----|
| **ひみつの値** | APIキー、データベースのパスワード |
| **場所によって変わる値** | データベースの場所（自分のPC か 本番のサーバーか）、API の URL |

> 💡 **たとえるなら「家のカギ」**
> 家の **設計図**（プログラム）は、ほかの人に見せても大丈夫です。
> でも、**カギ**（パスワード）は設計図にはりつけず、**別に持って** おきますよね。
> 環境変数は、プログラムとは別に持っておく **カギ** のようなものです。

---

## 2. なぜ環境変数を使うの？

### ① ひみつの値を GitHub にのせないため

APIキーをプログラムに **直接書いて** GitHub に公開すると、**世界中の誰でも見られます**。

```js
// ✕ 危ない：コードに直接書いている
const apiKey = "sk-abc123xyz...";
```

```js
// ◯ 安全：環境変数から読みこむ
const apiKey = process.env.WEATHER_API_KEY;
```

> ⚠️ **GitHub にのせたキーは、すぐに悪用される**
> 公開リポジトリにのったキーを、自動で探しているプログラムがあります。
> まちがえてプッシュしてしまったら、**コミットを消すだけではダメ** です（履歴に残っています）。
> すぐにサービスの管理画面で **キーを無効にして、新しいキーを作り直し** ましょう。

### ② 場所によって値を切りかえるため

同じプログラムでも、**自分のPC** と **本番（Vercel など）** では、つなぐ先がちがいます。

| | 自分のPC（開発環境） | 本番環境 |
|---|---|---|
| データベース | 自分のPCの MySQL | ネット上のデータベース |
| API の URL | `http://localhost:8000` | `https://〇〇.com` |

プログラムは **そのまま**、環境変数だけを変えれば、つなぐ先を切りかえられます。
「**環境** によって変わる **変数**」だから、**環境変数** という名前です。

---

## 3. `.env` ファイル

開発中は、`.env` という名前のファイルに環境変数を書きます。

### Laravel の場合（`.env`）

```
APP_NAME=BookApp
DB_HOST=127.0.0.1
DB_DATABASE=laravel
DB_USERNAME=laravel
DB_PASSWORD=password
```

```php
// 読みこむとき（config ファイルの中で）
'database' => env('DB_DATABASE'),
```

### Next.js の場合（`.env.local`）

```
WEATHER_API_KEY=abc123xyz
NEXT_PUBLIC_SUPABASE_URL=https://〇〇.supabase.co
```

```js
// 読みこむとき
const apiKey = process.env.WEATHER_API_KEY;
```

> ⚠️ **Next.js の `NEXT_PUBLIC_` に注意**
> 名前が `NEXT_PUBLIC_` で始まる環境変数は、**ブラウザに送られて、だれでも見られます**。
> **ひみつの値（APIキーなど）には、`NEXT_PUBLIC_` をつけない** ようにしましょう。
> `NEXT_PUBLIC_` がない環境変数は、サーバー側（Server Components や Route Handlers）でだけ使えます。

> 📝 Supabase の **URL と公開用のキー（publishable key / anon key）** は、ブラウザで使う前提のものなので `NEXT_PUBLIC_` をつけて大丈夫です。
> そのかわり、データを守るために **RLS** を必ず設定します（→ [認証と認可について](../2026_11_13/認証と認可について.md)）。
> 一方、**secret key / service_role key** は何でもできてしまうキーなので、ぜったいに `NEXT_PUBLIC_` をつけてはいけません。

## 4. `.env` を GitHub にのせないしくみ

`.env` が GitHub にのらないのは、**`.gitignore`** に書かれているからです。

```
# .gitignore
.env
.env*.local
```

`.gitignore` に書かれたファイルは、**Git が無視する** ので、コミットされません。
Laravel や `create-next-app` で作ったプロジェクトには、**最初から書かれて** います。

### `.env.example` を用意する

`.env` は GitHub にのらないので、ほかの人が見ても **どんな環境変数が必要か** がわかりません。
そこで、**値をからにしたお手本** の `.env.example` を作って GitHub にのせます。

```
# .env.example（GitHub にのせる）
WEATHER_API_KEY=
NEXT_PUBLIC_SUPABASE_URL=
```

> 💡 Laravel には、最初から `.env.example` があります。ポートフォリオとして見せるときも、`.env.example` があると **ちゃんとしている** 印象になります。

---

## 5. 本番（Vercel）では管理画面で設定する

`.env.local` は GitHub にのらないので、**Vercel には届きません**。
本番の環境変数は、Vercel の管理画面で設定します。

```mermaid
graph LR
    A[Vercel の<br>プロジェクト] --> B[Settings] --> C[Environment<br>Variables] --> D[名前と値を<br>入力して保存]
    D --> E[もう一度<br>デプロイする]
```

> ⚠️ **環境変数を追加・変更したら、もう一度デプロイする**
> 環境変数は、**デプロイするときに** 読みこまれます。設定しただけでは、今動いているサイトには反映されません。

---

## 6. まとめ

- **環境変数** ＝ プログラムの **外側** に置いておく設定の値
- 使う理由は、**ひみつの値を守る** ため、**環境によって値を切りかえる** ため
- 開発中は **`.env`**（Next.js は `.env.local`）に書く。**`.gitignore`** で GitHub にのらない
- 必要な環境変数のお手本として **`.env.example`** を GitHub にのせる
- Next.js の **`NEXT_PUBLIC_`** はブラウザで丸見え。ひみつの値にはつけない
- 本番（Vercel）は **管理画面で設定** して、**もう一度デプロイ**
- キーをプッシュしてしまったら、**すぐに無効にして作り直す**
