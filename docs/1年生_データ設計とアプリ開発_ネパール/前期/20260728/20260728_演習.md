## अभ्यास 1: आधारभूत SELECT

```sql
-- ① orders टेबलका सबै डाटा देखाउनुहोस्
--    अपेक्षित नतिजा: 5 वटा (कक्षा 09 मा दर्ता गरेका सबै अर्डर डाटा)

-- ② products टेबलबाट price 5000 येन वा सोभन्दा बढी भएका सामान निकाल्नुहोस्
--    अपेक्षित नतिजा: ノートPC(98000), キーボード(8500) गरी 2 वटा (マウス पर्दैन)

-- ③ users टेबलका user हरूलाई id को घट्दो क्रममा देखाउनुहोस्
--    अपेक्षित नतिजा: 山田次郎(id=3) → 鈴木花子(id=2) → 田中太郎(id=1) को क्रममा

-- ④ products टेबलबाट सबैभन्दा महँगो र सबैभन्दा सस्तो सामानको मूल्य देखाउनुहोस्
--    अपेक्षित नतिजा: सबैभन्दा महँगो 98000 / सबैभन्दा सस्तो 3200
```

## अभ्यास 2: INSERT / UPDATE / DELETE

```sql
-- ① तलको user थप्नुहोस्
--    नाम: 中村健二, इमेल: nakamura@example.com
--    अपेक्षित नतिजा: id=4 को रूपमा 中村健二 थपिन्छ

-- ② products टेबलमा 「USBハブ」(USB hub, मूल्य: 2800 येन) थप्नुहोस्
--    अपेक्षित नतिजा: id=4 को रूपमा USBハブ(2800 येन) थपिन्छ

-- ③ 田中太郎 ले USBハブ 3 वटा अर्डर गरेको रेकर्ड orders मा थप्नुहोस्
--    संकेत: पहिले 田中太郎 को id र USBハブ को id SELECT ले जाँच्नुहोस्
--    (2 चरणमा गरे पनि हुन्छ। एउटै statement मा लेख्न चाहनेले सामग्रीको अध्याय 8 "सबक्वेरी" हेर्नुहोस्)
--    अपेक्षित नतिजा: id=6 को अर्डरको रूपमा (user_id=1, product_id=4, quantity=3) थपिन्छ

-- ④ ノートPC को मूल्य 95000 येनमा अपडेट गर्नुहोस्
--    संकेत: SELECT ले जाँचेर मात्र UPDATE गर्नुहोस्
--    अपेक्षित नतिजा: ノートPC को price 98000 → 95000 मा परिवर्तन हुन्छ

-- ⑤ थपेको 中村健二 को अर्डर डाटा छ भने मेटाउनुहोस्, त्यसपछि 中村健二 आफैंलाई मेटाउनुहोस्
--    संकेत: फरेन की constraint भएकाले, पहिले orders मेटाउनुपर्छ
--    संकेत: 中村健二 को id थाहा नभए पनि, सामग्रीको अध्याय 8 "सबक्वेरी" मा दिइएको तरिका प्रयोग गरेर
--    (SELECT id FROM users WHERE name = '中村健二') को सहायताले एउटै statement मा लेख्न सकिन्छ
--    अपेक्षित नतिजा: 中村健二 को अर्डर 0 वटा भएकाले पहिलो DELETE ले 0 row मेटाउँछ,
--    दोस्रो DELETE ले 中村健二(id=4) लाई मेटाउँछ
```

## अभ्यास 3: JOIN र गणना (aggregation)

(अभ्यास 2 का परिवर्तन लागू गर्नुअघिको, कक्षा 09 को सुरुको डाटालाई आधार मानेर सोच्नुहोस्)

```sql
-- ① सबै अर्डरलाई "user नाम・सामानको नाम・संख्या・कुल रकम" को ढाँचामा देखाउनुहोस्
--    अपेक्षित नतिजा: 5 row (田中太郎×2, 鈴木花子×2, 山田次郎×1)

-- ② 田中太郎 का अर्डरहरूको सूची सामानको नाम र रकमसहित देखाउनुहोस्
--    अपेक्षित नतिजा: ノートPC(1 वटा, 98000 येन), マウス(2 वटा, 6400 येन) गरी 2 row

-- ③ सामान अनुसारको कुल बिक्रीलाई "सामानको नाम・बिक्री संख्या・कुल बिक्री" को ढाँचामा
--    कुल बिक्रीको घट्दो क्रममा देखाउनुहोस्
--    अपेक्षित नतिजा: ノートPC(3 वटा, 294000 येन) → キーボード(1 वटा, 8500 येन) → マウス(2 वटा, 6400 येन)

-- ④ अहिलेसम्म कहिल्यै अर्डर नगरेका user खोज्नुहोस्
--    संकेत: LEFT JOIN + WHERE orders.id IS NULL प्रयोग गर्नुहोस्
--    (यो ढाँचाको व्याख्याका लागि सामग्रीको 5-1 "अहिलेसम्म अर्डर नगरेका user मात्र खोज्ने" हेर्नुहोस्)
--    अपेक्षित नतिजा: 0 वटा (सुरुको डाटामा सबैले कम्तीमा 1 पटक अर्डर गरिसकेकाले)
```

## अभ्यास 4: थप चुनौतीपूर्ण प्रश्न (ऐच्छिक・समय बाँकी भएमा प्रयास गर्नुहोस्)

अभ्यास 1〜3 गर्न सके आजको लक्ष्य पूरा हुन्छ। अभ्यास 4 मा `HAVING` जस्ता नयाँ कुरा भएकाले,
सबै प्रश्न हल गर्नैपर्छ भन्ने छैन। (यसमा पनि कक्षा 09 को सुरुको डाटालाई आधार मानेर सोच्नुहोस्)

```sql
-- ① प्रतिव्यक्ति औसत खरिद रकम सबैभन्दा बढी भएको user पत्ता लगाउनुहोस्
--    अपेक्षित नतिजा: 山田次郎 (औसत 98000 येन। 田中太郎 52200 येन, 鈴木花子 53250 येन)

-- ② हरेक user को "सबैभन्दा पछिल्लो अर्डरको मिति र समय" देखाउनुहोस्
--    संकेत: GROUP BY + MAX(ordered_at)
--    अपेक्षित नतिजा: सुरुको डाटा एउटै INSERT ले एकै पटक दर्ता गरिएकाले, तीनै जनाको मिति र समय उही हुन्छ

-- ③ कुल अर्डर रकम 100000 येन वा सोभन्दा बढी भएका user को नाम र इमेल देखाउनुहोस्
--    संकेत: GROUP BY + HAVING SUM(...) >= 100000
--    (WHERE र HAVING को फरकका लागि सामग्रीको अध्याय 7 "HAVING" हेर्नुहोस्)
--    अपेक्षित नतिजा: 田中太郎(104400 येन), 鈴木花子(106500 येन) गरी 2 जना (山田次郎 98000 येन पर्दैन)
```
