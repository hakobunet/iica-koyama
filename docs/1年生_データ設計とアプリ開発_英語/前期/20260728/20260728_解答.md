# Lesson 10 Exercises | Sample Answers

> 🇯🇵 Original (Japanese version): [20260728_解答.md](<../../../1年生_データ設計とアプリ開発/前期/20260728/20260728_解答.md>) <!-- original-ja-link -->

These are sample answers based on the initial data in the users / products / orders tables of `school_db` (see the Lesson 09 materials).
Unless stated otherwise, Exercises 1, 3, and 4 are based on "the initial data before running Exercise 2"
(Exercise 2 is treated as a continuous series of operations, run in order from ① to ⑤).

```
users table (initial data)
id │ name     │ email
───┼──────────┼────────────────────
 1 │ 田中太郎 │ tanaka@example.com
 2 │ 鈴木花子 │ suzuki@example.com
 3 │ 山田次郎 │ yamada@example.com

products table (initial data)
id │ name       │ price
───┼────────────┼───────
 1 │ ノートPC   │ 98000
 2 │ マウス     │  3200
 3 │ キーボード │  8500

orders table (initial data)
id │ user_id │ product_id │ quantity
───┼─────────┼────────────┼─────────
 1 │    1    │     1      │    1     -- 田中太郎: ノートPC ×1
 2 │    1    │     2      │    2     -- 田中太郎: マウス ×2
 3 │    2    │     3      │    1     -- 鈴木花子: キーボード ×1
 4 │    3    │     1      │    1     -- 山田次郎: ノートPC ×1
 5 │    2    │     1      │    1     -- 鈴木花子: ノートPC ×1
```

## Exercise 1: Basic SELECT

### ①

```sql
SELECT * FROM orders;
```

**Result (for reference):** All 5 rows of initial data shown above are displayed unchanged (`ordered_at` contains the date and time at the moment the rows were inserted).

### ②

```sql
SELECT * FROM products WHERE price >= 5000;
```

**Result (for reference):**

| name | price |
|------|-------|
| ノートPC | 98000 |
| キーボード | 8500 |

マウス (3200 yen) costs less than 5000 yen, so it is not included.

### ③

```sql
SELECT * FROM users ORDER BY id DESC;
```

**Result (for reference):** The users are displayed in the order 山田次郎 (id=3) → 鈴木花子 (id=2) → 田中太郎 (id=1).

### ④

```sql
SELECT MAX(price) AS 最高額, MIN(price) AS 最安値 FROM products;
```

**Result (for reference):** 最高額 (highest) = 98000 (ノートPC), 最安値 (lowest) = 3200 (マウス)

## Exercise 2: INSERT / UPDATE / DELETE

### ①

```sql
INSERT INTO users (name, email) VALUES ('中村健二', 'nakamura@example.com');
```

**Result (for reference):** "中村健二" is added with `id=4`.

### ②

```sql
INSERT INTO products (name, price) VALUES ('USBハブ', 2800);
```

**Result (for reference):** "USBハブ" is added with `id=4`.

### ③

```sql
-- First, check the ids
SELECT id FROM users WHERE name = '田中太郎';     -- → 1
SELECT id FROM products WHERE name = 'USBハブ';   -- → 4

-- Add the order using the IDs you found
INSERT INTO orders (user_id, product_id, quantity) VALUES (1, 4, 3);
```

**Result (for reference):** An order with `id=6` is added, recording that "田中太郎 ordered 3 USBハブ."

### ④

```sql
-- Check beforehand
SELECT * FROM products WHERE name = 'ノートPC';

UPDATE products SET price = 95000 WHERE name = 'ノートPC';
```

**Result (for reference):** The price of ノートPC changes from 98000 yen to 95000 yen.

### ⑤

```sql
-- Because of the foreign key constraint, delete from orders first, then users
DELETE FROM orders
WHERE user_id = (SELECT id FROM users WHERE name = '中村健二');

DELETE FROM users WHERE name = '中村健二';
```

**Result (for reference):** 中村健二 didn't place any orders in this exercise, so the first `DELETE` affects **0 rows** (nothing is deleted, which is a normal result). The second `DELETE` deletes 中村健二 (id=4).
The key point is that if you try to delete from `users` first, you get an error because of the foreign key constraint (this time it doesn't matter, because 中村健二 has no orders, but it's important to get into the habit of following the correct order).

## Exercise 3: JOIN and Aggregation

### ①

```sql
SELECT
    users.name      AS ユーザー名,
    products.name   AS 商品名,
    orders.quantity AS 数量,
    products.price * orders.quantity AS 合計金額
FROM orders
INNER JOIN users    ON orders.user_id    = users.id
INNER JOIN products ON orders.product_id = products.id
ORDER BY orders.id;
```

**Result (for reference):**

| ユーザー名 | 商品名 | 数量 | 合計金額 |
|---|---|---|---|
| 田中太郎 | ノートPC | 1 | 98000 |
| 田中太郎 | マウス | 2 | 6400 |
| 鈴木花子 | キーボード | 1 | 8500 |
| 山田次郎 | ノートPC | 1 | 98000 |
| 鈴木花子 | ノートPC | 1 | 98000 |

### ②

```sql
SELECT
    products.name   AS 商品名,
    orders.quantity AS 数量,
    products.price * orders.quantity AS 金額
FROM orders
INNER JOIN users    ON orders.user_id    = users.id
INNER JOIN products ON orders.product_id = products.id
WHERE users.name = '田中太郎';
```

**Result (for reference):**

| 商品名 | 数量 | 金額 |
|---|---|---|
| ノートPC | 1 | 98000 |
| マウス | 2 | 6400 |

### ③

```sql
SELECT
    products.name AS 商品名,
    SUM(orders.quantity) AS 販売数量,
    SUM(products.price * orders.quantity) AS 売上合計
FROM orders
INNER JOIN products ON orders.product_id = products.id
GROUP BY products.id, products.name
ORDER BY 売上合計 DESC;
```

**Result (for reference):**

| 商品名 | 販売数量 | 売上合計 |
|---|---|---|
| ノートPC | 3 | 294000 |
| キーボード | 1 | 8500 |
| マウス | 2 | 6400 |

### ④

```sql
SELECT users.name, users.email
FROM users
LEFT JOIN orders ON users.id = orders.user_id
WHERE orders.id IS NULL;
```

**Result (for reference):** In the initial data, every user (田中太郎, 鈴木花子, and 山田次郎) has ordered at least once, so **the result is 0 rows**.
(If 中村健二, whom you added in Exercise 2, hadn't been deleted yet at this point, exactly 1 row would match: 中村健二, who has no orders. The key point of this question is that "when there are no users with 0 orders, 0 rows is also a correct result.")

## Exercise 4: Challenge Questions

### ①

```sql
SELECT
    users.name AS ユーザー名,
    AVG(products.price * orders.quantity) AS 平均購入金額
FROM orders
INNER JOIN users    ON orders.user_id    = users.id
INNER JOIN products ON orders.product_id = products.id
GROUP BY users.id, users.name
ORDER BY 平均購入金額 DESC
LIMIT 1;
```

**Result (for reference):** The average purchase amount per order is 田中太郎 = (98000+6400)/2 = 52200 yen, 鈴木花子 = (8500+98000)/2 = 53250 yen, and 山田次郎 = 98000 yen (only 1 order). So **山田次郎 (98000 yen)** has the highest.

### ②

```sql
SELECT
    users.name AS ユーザー名,
    MAX(orders.ordered_at) AS 最新注文日時
FROM orders
INNER JOIN users ON orders.user_id = users.id
GROUP BY users.id, users.name;
```

**Result (for reference):** The initial data was inserted all at once with a single `INSERT` statement, so `ordered_at` is the same date and time (the moment the statement ran) for all 3 users. If you add orders on different days, you'll be able to see a different "most recent order date and time" for each user.

### ③

```sql
SELECT
    users.name  AS ユーザー名,
    users.email AS メール
FROM orders
INNER JOIN users    ON orders.user_id    = users.id
INNER JOIN products ON orders.product_id = products.id
GROUP BY users.id, users.name, users.email
HAVING SUM(products.price * orders.quantity) >= 100000;
```

**Result (for reference):**

| ユーザー名 | メール |
|---|---|
| 田中太郎 | tanaka@example.com |
| 鈴木花子 | suzuki@example.com |

田中太郎's total purchase amount is 104400 yen and 鈴木花子's is 106500 yen, so both are 100000 yen or more. 山田次郎's is 98000 yen, so he is not included.
