# コマ10 演習｜解答例

`school_db` の users / products / orders の初期データ（コマ09資料参照）をもとにした解答例です。
演習1・演習3・演習4は、特に断りがない限り「演習2を実行する前の初期データ」を基準に考えます
（演習2は①→⑤の順に実行する、連続した操作として扱います）。

```
users テーブル（初期データ）
id │ name     │ email
───┼──────────┼────────────────────
 1 │ 田中太郎 │ tanaka@example.com
 2 │ 鈴木花子 │ suzuki@example.com
 3 │ 山田次郎 │ yamada@example.com

products テーブル（初期データ）
id │ name       │ price
───┼────────────┼───────
 1 │ ノートPC   │ 98000
 2 │ マウス     │  3200
 3 │ キーボード │  8500

orders テーブル（初期データ）
id │ user_id │ product_id │ quantity
───┼─────────┼────────────┼─────────
 1 │    1    │     1      │    1     -- 田中太郎: ノートPC ×1
 2 │    1    │     2      │    2     -- 田中太郎: マウス ×2
 3 │    2    │     3      │    1     -- 鈴木花子: キーボード ×1
 4 │    3    │     1      │    1     -- 山田次郎: ノートPC ×1
 5 │    2    │     1      │    1     -- 鈴木花子: ノートPC ×1
```

---

## 演習1：基本 SELECT

### ①

```sql
SELECT * FROM orders;
```

**結果（参考）：** 上記の初期データ5件がそのまま表示される（`ordered_at` には INSERT した瞬間の日時が入る）。

### ②

```sql
SELECT * FROM products WHERE price >= 5000;
```

**結果（参考）：**

| name | price |
|------|-------|
| ノートPC | 98000 |
| キーボード | 8500 |

マウス（3200円）は5000円未満なので対象外。

### ③

```sql
SELECT * FROM users ORDER BY id DESC;
```

**結果（参考）：** 山田次郎(id=3) → 鈴木花子(id=2) → 田中太郎(id=1) の順で表示される。

### ④

```sql
SELECT MAX(price) AS 最高額, MIN(price) AS 最安値 FROM products;
```

**結果（参考）：** 最高額 = 98000（ノートPC）、最安値 = 3200（マウス）

## 演習2：INSERT / UPDATE / DELETE

### ①

```sql
INSERT INTO users (name, email) VALUES ('中村健二', 'nakamura@example.com');
```

**結果（参考）：** `id=4` として「中村健二」が追加される。

### ②

```sql
INSERT INTO products (name, price) VALUES ('USBハブ', 2800);
```

**結果（参考）：** `id=4` として「USBハブ」が追加される。

### ③

```sql
-- まず id を確認する
SELECT id FROM users WHERE name = '田中太郎';     -- → 1
SELECT id FROM products WHERE name = 'USBハブ';   -- → 4

-- 確認した id を使って注文を追加
INSERT INTO orders (user_id, product_id, quantity) VALUES (1, 4, 3);
```

**結果（参考）：** `id=6` の注文として「田中太郎がUSBハブを3個」注文したデータが追加される。

### ④

```sql
-- 事前に確認
SELECT * FROM products WHERE name = 'ノートPC';

UPDATE products SET price = 95000 WHERE name = 'ノートPC';
```

**結果（参考）：** ノートPCの価格が 98000円 → 95000円 に変わる。

### ⑤

```sql
-- 外部キー制約があるため、orders → users の順で削除する
DELETE FROM orders
WHERE user_id = (SELECT id FROM users WHERE name = '中村健二');

DELETE FROM users WHERE name = '中村健二';
```

**結果（参考）：** 中村健二はこの演習内で注文を1件も追加していないため、1つ目の `DELETE` は**対象0件**（何も削除されない＝正常な結果）。2つ目の `DELETE` で中村健二(id=4)が削除される。
先に `users` を消そうとすると外部キー制約でエラーになる点がポイント（今回は中村健二の注文が実際には無いので影響は出ないが、順番を守る習慣が重要）。

## 演習3：JOIN と集計

### ①

```sql
SELECT
    users.name      AS ユーザー名,
    products.name   AS 商品名,
    orders.quantity AS 数量,
    products.price * orders.quantity AS 合計金額
FROM orders
INNER JOIN users    ON orders.user_id    = users.id
INNER JOIN products ON orders.product_id = products.id
ORDER BY orders.id;
```

**結果（参考）：**

| ユーザー名 | 商品名 | 数量 | 合計金額 |
|---|---|---|---|
| 田中太郎 | ノートPC | 1 | 98000 |
| 田中太郎 | マウス | 2 | 6400 |
| 鈴木花子 | キーボード | 1 | 8500 |
| 山田次郎 | ノートPC | 1 | 98000 |
| 鈴木花子 | ノートPC | 1 | 98000 |

### ②

```sql
SELECT
    products.name   AS 商品名,
    orders.quantity AS 数量,
    products.price * orders.quantity AS 金額
FROM orders
INNER JOIN users    ON orders.user_id    = users.id
INNER JOIN products ON orders.product_id = products.id
WHERE users.name = '田中太郎';
```

**結果（参考）：**

| 商品名 | 数量 | 金額 |
|---|---|---|
| ノートPC | 1 | 98000 |
| マウス | 2 | 6400 |

### ③

```sql
SELECT
    products.name AS 商品名,
    SUM(orders.quantity) AS 販売数量,
    SUM(products.price * orders.quantity) AS 売上合計
FROM orders
INNER JOIN products ON orders.product_id = products.id
GROUP BY products.id, products.name
ORDER BY 売上合計 DESC;
```

**結果（参考）：**

| 商品名 | 販売数量 | 売上合計 |
|---|---|---|
| ノートPC | 3 | 294000 |
| キーボード | 1 | 8500 |
| マウス | 2 | 6400 |

### ④

```sql
SELECT users.name, users.email
FROM users
LEFT JOIN orders ON users.id = orders.user_id
WHERE orders.id IS NULL;
```

**結果（参考）：** 初期データでは田中太郎・鈴木花子・山田次郎の全員が最低1回は注文しているため、**結果は0件**。
（演習2で追加した中村健二をこの時点でまだ削除していない状態であれば、注文が無い中村健二が1件だけヒットする。「注文0件のユーザーがいない＝0件もまた正しい結果」という点がこの問題のポイント。）

## 演習4：応用問題

### ①

```sql
SELECT
    users.name AS ユーザー名,
    AVG(products.price * orders.quantity) AS 平均購入金額
FROM orders
INNER JOIN users    ON orders.user_id    = users.id
INNER JOIN products ON orders.product_id = products.id
GROUP BY users.id, users.name
ORDER BY 平均購入金額 DESC
LIMIT 1;
```

**結果（参考）：** 1注文あたりの平均購入金額は、田中太郎 = (98000+6400)/2 = 52200円、鈴木花子 = (8500+98000)/2 = 53250円、山田次郎 = 98000円（注文1件のみ）。よって **山田次郎（98000円）** が最も高い。

### ②

```sql
SELECT
    users.name AS ユーザー名,
    MAX(orders.ordered_at) AS 最新注文日時
FROM orders
INNER JOIN users ON orders.user_id = users.id
GROUP BY users.id, users.name;
```

**結果（参考）：** 初期データは1つの `INSERT` 文でまとめて登録したため、`ordered_at` は3人とも実行した瞬間の同じ日時になる。日を分けて注文を追加すれば、ユーザーごとに異なる「最新の注文日時」が確認できるようになる。

### ③

```sql
SELECT
    users.name  AS ユーザー名,
    users.email AS メール
FROM orders
INNER JOIN users    ON orders.user_id    = users.id
INNER JOIN products ON orders.product_id = products.id
GROUP BY users.id, users.name, users.email
HAVING SUM(products.price * orders.quantity) >= 100000;
```

**結果（参考）：**

| ユーザー名 | メール |
|---|---|
| 田中太郎 | tanaka@example.com |
| 鈴木花子 | suzuki@example.com |

田中太郎の合計購入額は 104400円、鈴木花子は 106500円でどちらも100000円以上。山田次郎は 98000円のため対象外。
