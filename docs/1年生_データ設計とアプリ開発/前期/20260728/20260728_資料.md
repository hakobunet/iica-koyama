## 1. なぜテーブルを分けるのか

悪い例：全部1テーブルに詰め込む

```
orders テーブル（悪い例）
id │ user_name │ user_email         │ product_name │ price
───┼───────────┼────────────────────┼──────────────┼───────
 1 │ 田中太郎  │ tanaka@example.com │ ノートPC     │ 98000
 2 │ 田中太郎  │ tanaka@example.com │ マウス       │  3200
 3 │ 鈴木花子  │ suzuki@example.com │ キーボード   │  8500
```

**問題点：**
- 田中太郎の情報が2行に重複している（メールが変わったら全行更新が必要）
- データが矛盾しやすい

**解決策：テーブルを分けて外部キーで結ぶ（正規化）**

---

## 2. 外部キー（Foreign Key）

```
users テーブル                orders テーブル
───────────────               ──────────────────────────────
id │ name     │ email         id │ user_id │ product │ price
───┼──────────┼────────       ───┼─────────┼─────────┼───────
 1 │ 田中太郎 │ tanaka@...     1 │    1    │ ノートPC│ 98000
 2 │ 鈴木花子 │ suzuki@...     2 │    1    │ マウス  │  3200
                               3 │    2    │ キーボ  │  8500
                                     ↑
                             orders.user_id が users.id を参照
                             これが「外部キー（Foreign Key）」
```

## 3. テーブルの作成と外部キーの設定

```sql
USE school_db;

-- users テーブル
CREATE TABLE users (
    id    INT AUTO_INCREMENT PRIMARY KEY,
    name  VARCHAR(100) NOT NULL,
    email VARCHAR(255) NOT NULL UNIQUE
);

-- products テーブル
CREATE TABLE products (
    id    INT AUTO_INCREMENT PRIMARY KEY,
    name  VARCHAR(100) NOT NULL,
    price INT NOT NULL
);

-- orders テーブル（外部キーで結ぶ）
CREATE TABLE orders (
    id         INT AUTO_INCREMENT PRIMARY KEY,
    user_id    INT NOT NULL,
    product_id INT NOT NULL,
    quantity   INT NOT NULL DEFAULT 1,
    ordered_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    
    -- 外部キー制約（参照整合性を保つ）
    FOREIGN KEY (user_id)    REFERENCES users(id),
    FOREIGN KEY (product_id) REFERENCES products(id)
);

-- テストデータ
INSERT INTO users (name, email) VALUES
    ('田中太郎', 'tanaka@example.com'),
    ('鈴木花子', 'suzuki@example.com'),
    ('山田次郎', 'yamada@example.com');

INSERT INTO products (name, price) VALUES
    ('ノートPC', 98000),
    ('マウス', 3200),
    ('キーボード', 8500);

INSERT INTO orders (user_id, product_id, quantity) VALUES
    (1, 1, 1),  -- 田中がノートPCを1台
    (1, 2, 2),  -- 田中がマウスを2個
    (2, 3, 1),  -- 鈴木がキーボードを1個
    (3, 1, 1),  -- 山田がノートPCを1台
    (2, 1, 1);  -- 鈴木がノートPCを1台
```

## 4. INNER JOIN — 両方に存在するデータだけ結合

```sql
-- orders に users の情報を結合
SELECT
    orders.id,
    users.name    AS ユーザー名,
    users.email,
    orders.quantity
FROM orders
INNER JOIN users ON orders.user_id = users.id;

-- 3テーブルを結合（orders + users + products）
SELECT
    orders.id,
    users.name      AS ユーザー名,
    products.name   AS 商品名,
    products.price  AS 単価,
    orders.quantity AS 数量,
    products.price * orders.quantity AS 合計金額
FROM orders
INNER JOIN users    ON orders.user_id    = users.id
INNER JOIN products ON orders.product_id = products.id
ORDER BY orders.id;
```

## 5. LEFT JOIN — 左テーブルの全行を含める

```sql
-- まだ注文していないユーザーも含めて表示したい場合
SELECT
    users.name,
    COUNT(orders.id) AS 注文数
FROM users
LEFT JOIN orders ON users.id = orders.user_id
GROUP BY users.id, users.name;

-- 注文0件のユーザーも表示される
-- INNER JOIN だと注文ありのユーザーだけになる
```

### 5-1. 応用：まだ注文していないユーザー「だけ」を探す

LEFT JOINで結合したとき、右側（orders）に一致する行がないと、その列は`NULL`になります。この性質を使うと「未一致の行だけ」を絞り込めます。

```sql
SELECT users.name, users.email
FROM users
LEFT JOIN orders ON users.id = orders.user_id
WHERE orders.id IS NULL;
```

**考え方：**
1. `LEFT JOIN`で users 全員を残す（orders が無い人は各列が`NULL`になる）
2. `WHERE orders.id IS NULL` で「ordersと一致しなかった行」だけに絞る
   → つまり「一度も注文していない人」だけが残る

`INNER JOIN`ではこのパターンは使えません（一致しない行はそもそも結果に出てこないため）。「LEFT JOIN + `IS NULL`」は、この形でセットの定番パターンとして覚えておくと便利です。

## 6. 集計との組み合わせ

```sql
-- ユーザーごとの購入合計金額
SELECT
    users.name AS ユーザー名,
    COUNT(orders.id) AS 注文件数,
    SUM(products.price * orders.quantity) AS 合計金額
FROM users
INNER JOIN orders    ON users.id          = orders.user_id
INNER JOIN products  ON orders.product_id = products.id
GROUP BY users.id, users.name
ORDER BY 合計金額 DESC;
```

## 7. HAVING — 集計した「あと」で絞り込む

`WHERE`は集計する**前**の行を絞り込みますが、`HAVING`は`GROUP BY`で集計した**あと**の結果を絞り込みます。

```sql
-- 合計金額が 100000円 以上のユーザーだけを表示
SELECT
    users.name AS ユーザー名,
    SUM(products.price * orders.quantity) AS 合計金額
FROM users
INNER JOIN orders   ON users.id          = orders.user_id
INNER JOIN products ON orders.product_id = products.id
GROUP BY users.id, users.name
HAVING SUM(products.price * orders.quantity) >= 100000;
```

**WHERE と HAVING の違い：**

| | いつ絞り込む | 使えるもの |
|---|---|---|
| `WHERE` | `GROUP BY`で集計する**前** | 各行の生の列（`orders.quantity`など） |
| `HAVING` | `GROUP BY`で集計した**後** | `SUM()` `COUNT()` などの集計結果 |

`SELECT ... FROM ... WHERE ... GROUP BY ... HAVING ... ORDER BY`の順で書きますが、実際に処理されるのは`WHERE`→`GROUP BY`→`HAVING`→`ORDER BY`の順です。「`HAVING SUM(...) >= 100000`はOK、`WHERE SUM(...) >= 100000`はNG（集計前なのでSUMがまだ存在しない）」と覚えておきましょう。

## 8. サブクエリ — SELECTの中にSELECTを書く

`INSERT`や`DELETE`をするとき、対象の`id`が分からないことがあります。そんなときは`SELECT`の結果をそのまま条件として使う**サブクエリ**が便利です。

```sql
-- 例：「田中太郎」の id を条件に使いたいが、id が何番か分からない

-- ① 悪い例ではないが、2手順に分かれる
SELECT id FROM users WHERE name = '田中太郎';  -- 結果: 1
DELETE FROM orders WHERE user_id = 1;          -- 確認した 1 を手で入力する

-- ② サブクエリを使うと1文で書ける
DELETE FROM orders
WHERE user_id = (SELECT id FROM users WHERE name = '田中太郎');
```

`( )`の中の`SELECT`が先に実行されて1つの値（ここでは`id`）になり、外側の`WHERE user_id = ここ`に差し込まれるイメージです。「カッコの中を先に読む」と考えると分かりやすいです。

```sql
-- INSERT でも同様に使える例
INSERT INTO orders (user_id, product_id, quantity)
VALUES (
    (SELECT id FROM users WHERE name = '田中太郎'),
    (SELECT id FROM products WHERE name = 'USBハブ'),
    3
);
```

## まとめ

| 概念 | 説明 |
|------|------|
| 外部キー | 別テーブルの主キーを参照するカラム |
| INNER JOIN | 両テーブルに存在するデータだけを結合 |
| LEFT JOIN | 左テーブルの全行＋右テーブルの一致分を結合 |
| `ON テーブルA.col = テーブルB.col` | 結合条件 |
| LEFT JOIN + `WHERE ... IS NULL` | 右テーブルに一致しない行（未一致）だけを探す定番パターン |
| `WHERE` | 集計前の行を絞り込む |
| `HAVING` | `GROUP BY`で集計した後の結果を絞り込む |
| サブクエリ `(SELECT ...)` | `SELECT`の結果を、別のSQLの条件や値として埋め込む |
